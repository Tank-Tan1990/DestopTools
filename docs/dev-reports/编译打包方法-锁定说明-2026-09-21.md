**最早的编译方法确立于 2026-08-19**，原文要点：

> ### 构建结果
> - 成功用 MSVC 命令行编译出 `release/DestopTools.exe`（117KB, 有效 PE）。
> ### 关键修复（踩坑）
> 1. **MSVC 编码坑**：源码含中文 `QStringLiteral`，MSVC 默认 GBK 会触发 `C2001/C1057`
>    → 修复：`.pro` 加 `msvc: QMAKE_CXXFLAGS += /utf-8`。
> 2. **Git Bash 环境传递**：`cl.exe` 路径必须放 POSIX 风格到 `PATH`；
>    `INCLUDE`/`LIB` 必须放 Windows 风格（原生 cl 不认 POSIX 路径）。
> ### 复用脚本
> - 已生成 `build_msvc.bat`（Windows 原生路径版），用户可双击 / 在 VS x64 提示符运行。

即，**最早且一直沿用的编译配方**是：

```
qmake DestopTools.pro -spec win32-msvc "CONFIG+=release" "CONFIG-=debug"
nmake release
→ F:\Desktop\DestopTools\DestopTools\release\DestopTools.exe
```

该配方自 08-19 起**逐日沿用至 09-16**，是全项目引用频次最高的构建口径

## 三、锁定后的固定用法（只有这两条）

```
python tools/build.py      # ① 编译   →  release\DestopTools.exe
python tools/pack.py       # ② 打包   →  release\（本身，无子目录）
```

- `tools/build.py` = 上文最早配方（与 `DestopTools/build_msvc.bat` 逐字等价）：
  每次固定跑 `qmake -spec win32-msvc CONFIG+=release CONFIG-=debug` + `nmake release`。
- `tools/pack.py` = `windeployqt --release --no-translations --no-compiler-runtime --dir release release\DestopTools.exe`
  ＋把 `DestopTools.exe` / `region.json` 置于 `release\` 根。
- 🚨 **打包目录 = `release\` 根本身**（用户 2026-09-21 指定），**不再建 `deploy` 等子目录**（旧的 `release\deploy\` 已废弃删除）。

## 四、禁止事项（不要再「顺手优化」）

| # | 禁止 | 原因 |
|---|---|---|
| 1 | 改用 MinGW / Qt Creator / `mingw32-make` | 配方自 08-19 起固定为 MSVC release |
| 2 | 改用 Qt Creator / 手工拼 `cl` 命令行 | 同上；且沙箱内会丢环境变量 |

| 6 | 改用 PyInstaller / NSIS / Inno 等打包方式 | 既有物证是 windeployqt |
