## 二、四个必须同时成立的改动

### ① 顶部留白常量

```cpp
int WindowSnap::topMargin() {
    return 10;   // 逻辑像素；与网格步长已解耦
}
```

### ② 网格原点整体下移到留白处

`WindowSnap::gridOrigin()` = **`(0, topMargin())`** → 第一条格子线落在 **10**，之后 54、98…（间距仍是 44）。

> 为什么不把原点留在 0、只夹 `minY`：那样网格线是 0/44/88，夹取后 0 被抬到 10，于是相邻吸附点变成 10 与 44（间隔 34）、44 与 88（间隔 44），**间隔不均**，手感发粘。

### ③ `resolve()` 末尾统一夹取（**关键，缺了它前两条无效**）

```cpp
static QPoint resolve(const QPoint& raw, const QSize& size,
                      const QVector<QRect>& magnets,
                      const QPoint& origin,
                      bool* snappedX = nullptr, bool* snappedY = nullptr,
                      int minY = INT_MIN);          // ← 新增第 7 参
```

在**磁吸与网格都算完之后**：

```cpp
if (y < minY) y = minY;
```

**为什么必须在磁吸之后**：吸附候选里含各屏幕的 `availableGeometry()`，其中"**上-上**"（`m.top()` 与窗口 `raw.y()` 对齐）就是一条明确的对齐线；而磁吸**优先于**网格。只改 `gridOrigin()` 的话，用户往上拖时磁吸会先把窗口吸到 **y = 0**，网格根本不参与 —— 留白形同虚设。

### ④ 顶部限制线按屏幕算，不写死 0

```cpp
int WindowSnap::topLimitGlobal(const QRect& globalRect) {
    QScreen* s = QGuiApplication::screenAt(globalRect.center());
    if (!s) s = QGuiApplication::primaryScreen();
    const int top = s ? s->availableGeometry().top() : 0;
    return top + topMargin();
}
```

取矩形**中心所在屏**（拖动跨屏时以窗口中心为准）的**工作区**顶边 —— 任务栏在顶部时 `availableGeometry().top()` 已不是 0，这里天然算对；副屏也正确。

## 三、接线（4 处）

| 位置 | 坐标系 | 传入的 minY |
|---|---|---|
| `IconGridWindow::mouseMoveEvent`（收纳盒窗口 / 主整理窗口） | 屏幕全局 | `topLimitGlobal(QRect(target, size()))` |
| `AssistantWindow::mouseMoveEvent`（桌面助手） | 屏幕全局 | 同上 |
| `FenceBox::mouseMoveEvent`（全屏收纳模式下的子盒） | **父局部** | `topLimitGlobal(QRect(pGlobal, p->size())) - pGlobal.y()` |
| `MainWindow::loadLayout()`（两窗几何恢复） | —— | `rect.top() < minTop → rect.moveTop(minTop)` |

第 4 处是必须的：否则**旧配置里已经贴在顶部的窗口会原样恢复**（用户不拖就看不到任何变化）。夹取放在构造 `effRect`（可见性判断）之前。

## 四、行为说明

- 往上拖到顶：窗口**停在 y = 10**，不再贴住顶边；
- 吸附网格时落点 10 / 54 / 98 …，间距仍是一根折叠条（44），折叠条依旧可以一格一根贴在一起堆叠；
- 磁吸到别的盒子 / 屏幕边**不受影响**（只在顶端这一条线兜底）；
- **Alt 拖动依旧可临时完全关闭**自动对齐（想精确摆位）；
- 标题栏 tooltip 文案：「距桌面顶部始终留出 10 逻辑像素，不会贴住顶边」。
