## 一、需求

> 「dock内的图标，拖动到收纳盒，能否让拖动时跟随鼠标的图标，进入收纳盒时叠在收纳盒上面」
> 现场补充：「目前从 dock 拖拽到收纳盒时，图标被收纳盒遮住，只能看到鼠标」

即：拖动中跟随光标的那个图标，进入收纳盒范围时应**画在收纳盒之上**。

## 二、根因（两条叠加）

1. **Dock 层在最底**。Dock 就是 `DesktopMirrorWindow` —— 铺满主屏、`SetWindowPos(HWND_BOTTOM)` 压在
   最底的分层窗（`startMirror()` → `parkAllTargetsAtBottom()`，注释原文："Dock 最底，收纳盒/助手在其上"）。
   收纳盒窗口（`IconGridWindow`）是**不透明卡片面板**，永远盖在 Dock 之上。
2. **拖动图像＝被拖的那个真实控件**。Dock 的拖动是**自定义跟手移动**（`DockIconButton::mouseMoveEvent`
   → `dragMove` → `DesktopMirrorWindow::onIconDragMove` 对组内按钮 `move()`），**不走 `QDrag`**，
   没有系统拖拽图像层可言。

=> 光标一进到收纳盒窗口上，那个按钮就被盒窗整块盖住：指示线在、`DragMoveCursor` 在，唯独图标看不见。

## 三、方案取舍

| 方案 | 结论 |
|---|---|
| 拖动期把 Dock 抬到盒子上 | ❌ Dock 是整屏透明层，**全部**桌面图标会一起跑到盒子上面；顺带隐藏其它图标又会改变拖动期整屏观感，且与 3s 压底定时器/刷新打架 |
| 拖动期把被拖按钮 `setParent` 到浮层 | ❌ 按下时的隐式抓取在**原窗口 HWND**（Windows `SetCapture`）。换父后 `qt_button_down` 不再属于该窗口，Qt 会改派给窗口本身 → **拖动断在半途** |
| 用 `setMask`(SetWindowRgn) 裁剪浮层 | ❌ 分层窗（`UpdateLayeredWindow` per-pixel alpha）上行为未验证；而且**根本不需要** —— 半透明窗的透明像素天然透出下层 |
| **置顶浮层 + 只补画「与盒相交」那一块** | ✅ 采用 |

**为什么"只画那一块"是关键**：遮挡区之外真实按钮本来就正常可见，浮层若整块画就会与它**叠成重影**
（半透明像素二次混合会偏色、文字变粗）。

## 四、实现（3 个文件）

### 1. `desktopmirrorwindow.cpp` — 新类 `DockDragGhost`（文件内匿名 namespace）
```cpp
QWidget(nullptr, Qt::FramelessWindowHint | Qt::Tool | Qt::WindowStaysOnTopHint
                 | Qt::WindowDoesNotAcceptFocus | Qt::WindowTransparentForInput)
WA_TranslucentBackground + WA_ShowWithoutActivating + WA_TransparentForMouseEvents
paintEvent: p.setClipRect(m_clip);  然后按偏移画各图标位图
```
- 🚨 **必须不吃输入**：它一旦成为光标下的最上层窗口，就会抢走后续 move/release，拖动当场断。
- 🚨 `Qt::Tool` 是为了**不产生任务栏按钮**（无父顶层窗默认给 `WS_EX_APPWINDOW`）。
- 自带 `setStyleSheet("background: transparent; border: none;")` 挡应用级样式表；本类**无子控件**，
  故无选择器规则不会外溢（项目那条「设样式表必须带选择器」的坑在这里天然不适用，仍在注释里点明）。

### 2. `desktopmirrorwindow.h/.cpp` — 浮层四件套
- `setDragGhostClip(QRect)`：MainWindow 每次悬停（40ms 节流）下发"当前被遮挡的屏幕区域"，空＝未遮挡。
- `ensureDragGhostFrames()`：**每轮拖动只 `grab()` 一次**（`grab()` 是整控件重绘，逐帧抓会拖慢跟手度）；
  定位用**包围盒**（多选拖动时 `m_dragGroup.first()` 未必是最左上的那个 —— 与 `m_dragPrimary` 未必是首项同源）。
- `updateDragGhost()`：`bbox = 锚点当前全局位置 + 起抓偏移`；`inter = bbox ∩ 遮挡区`；`inter` 空则隐藏。
  尺寸在整段拖动中恒定 → 逐帧只 `move()` 不 `resize()`。
- `hideDragGhost()` / `resetDragGhost()`（隐藏 + 丢位图 + 清遮挡区）。

### 3. `icongridwindow.h/.cpp` — `externalDropSurfaceRectGlobal(gp)`
遮挡矩形判据（**纯几何，与"能不能投放"无关**）：
1. 命中某个 `FenceBox` → 返回该卡片矩形（盒内有底色，是遮挡物）；
2. `m_fencesMode`（全屏接管）→ 返回空（窗口铺满整屏但**背景完全透明**，盒外透出 Dock/壁纸，不遮挡）；
3. 其余（窗口化视图）→ 落在窗口内即返回整窗矩形（整扇窗口就是不透明卡片面板）。

### 4. `mainwindow.cpp`
- `onDockIconDragHover()`：遍历 `allBoxWindows()` 取第一个非空遮挡矩形 → `m_dock->setDragGhostClip()`。
- `onDockIconDragFinished()`：`setDragGhostClip(QRect())` 清空。

## 五、三个关键坑

1. 🚨 **遮挡判据必须与"能不能投放"分开算**。`resolveBoxAt` 走的是 `dropCategoryAtGlobal`
   （分类不可收纳/无有效分类时返回空），但图标照样被盒子盖住 —— 若复用 `hit` 判据，会出现
   "拖到某个盒子上依然看不见图标"。故遮挡区**独立遍历窗口几何**计算。
2. 🚨 **复位点必须齐（4 处）**：起拖前 `onIconPressed`（位图要重抓）、`abortActiveDrag`、`finishDrag`、
   `stopMirror`。浮层**无父对象**，`~DesktopMirrorWindow` 里须显式 `delete`（否则切模式/退出时留一层浮窗）。
3. **Qt 语义核实**（下载 Qt 5.14 `qwidget.cpp` 源码逐行核对，避免"抓图带未初始化像素"）：
   ```cpp
   QPixmap res((QSizeF(r.size()) * dpr).toSize());
   res.setDevicePixelRatio(dpr);
   if (!d->isOpaque) res.fill(Qt::transparent);   // ← 非不透明控件自动清透明
   d->render(&res, QPoint(), QRegion(r), DrawWindowBackground | DrawChildren | IgnoreMask);
   ```
   `isOpaque` 只由 `WA_OpaquePaintEvent` 决定；`DockIconButton` 未设（也无 `autoFillBackground`）→
   `grab()` 结果**必然已清成透明**，可直接用于半透明图标。顺带：拖动期 `paintEvent` 会
   `setOpacity(0.55)`（项目既有的"拖动半透明"观感），一并被抓进位图 → 浮层里的图标与真实图标观感一致。

## 七、请实测（关掉正在运行的程序后跑 `release\DestopTools.exe`）

1. 从 Dock 拖一个图标到**窗口化收纳盒**上 → 图标应**压在盒子上面**跟着光标走，不再"只剩鼠标"；
2. 拖着图标在盒子边缘来回移动 → 图标被盒子挡住的部分由浮层显示、露在盒子外的部分由真实图标显示，
   **交界处不应有重影/错位**；
3. 多选整组拖入 → 组内每个图标都应正常显示；
4. 拖到壁纸/盒外 → 浮层隐藏，图标恢复由真实按钮绘制（观感与改动前一致）；
5. 松手/中途 Esc → 图标落位正常，**不应残留任何"半透明图标残影"**；
6. 全屏接管模式（`FenceBox` 盒子）下拖入盒子 → 同款效果。

## 八、遗留（可选扩展，未做）

- **助手面板**（`SidePanelWidget`）同样位于 Dock 之上，拖到它上面图标也会被盖住 —— 本开关目前只覆盖
  收纳盒窗口；若要一并处理，在 `onDockIconDragHover` 的遮挡矩形计算里补上该窗口类型即可。
- 全屏接管模式右上角的**浮动搜索框 / 菜单按钮**会盖住图标，未纳入遮挡矩形（该模式下鼠标几乎总在窗口内，
  影响极小）。
