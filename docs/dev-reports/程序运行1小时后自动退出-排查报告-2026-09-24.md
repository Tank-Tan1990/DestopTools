### CrashTrace 的捕获范围（说明证据为何可信）

`crashtrace.cpp` 装了**四层兜底**，覆盖绝大多数崩溃形态：

1. `SetUnhandledExceptionFilter` → 捕获 **SEH 未处理异常**（访问违例 0xC0000005、栈溢出 0xC00000FD、堆损坏 0xC0000374…）
2. `std::set_terminate` → 捕获 `std::bad_alloc`、未捕获 C++ 异常等
3. `signal(SIGSEGV / SIGABRT / SIGILL / SIGFPE)` → 捕获 CRT 致命信号
4. Qt 消息处理器：`QtFatalMsg` 时**先写日志再 `abort()`**

> 即：**凡是能想到的崩溃，都会在 `DestopTools_crash.log` 留痕。而它一条都没有。**
> 剩下能绕过全部四层的只有：**外部 `TerminateProcess` 强杀**、**进程内 `ExitProcess` 直接调用**、**栈击穿到无可用栈**。

## 四、为什么「关掉窗口」不会让程序退出

`mainwindow.cpp:154`：

```cpp
// 任意子窗口（整理窗口/收纳盒/桌面助手）关闭都不自动退出程序，
// 仅在菜单"退出"时显式 qApp->quit()
QApplication::setQuitOnLastWindowClosed(false);
```

**推论**：程序"自己关闭"必然来自以下之一 ——

| 出口 | 位置 | 说明 |
|---|---|---|
| 侧栏菜单「退出桌面助手」 | `sidepanelwidget.cpp:1025` | 用 `chosen == exitAction` **指针比较**，写法正确 |

| 外部强杀 | — | 无日志 |

`applyBackupNow()` 会弹提示框：
> 「已选择备份「…」，程序将自动重启并应用该备份的桌面布局与全部配置。」

如果你 17:02 左右见过这个框，那这次的"关闭"就完全解释清楚了。

**已排除**：`categories.ini` 全文检索**不含**"退出"二字，所以不是"分类名恰好叫退出"误触发（缺陷 ⑤ 目前未命中）。

## 六、代码缺陷清单（**6 项，均已逐条亲自核实**）

> 说明：以下缺陷**均不是**本次"1 小时后退出"的根因（逐条给出理由），但都是**真实存在的隐患**，建议排期修复。**本轮未改动任何代码。**

### ① 🟡 静态裸指针 `g_self` 悬垂，析构不复位

- **位置**：`desktopmirrorwindow.cpp:155`（定义）→ `:169`（构造赋值）→ `:393`（使用）
- **问题**：`~DesktopMirrorWindow()`（`:262-270`）只做 `stopMirror()` + `delete m_dragGhost`，**从未 `g_self = nullptr`**。
- **使用点**：
  ```cpp
  // :392-393
  void DesktopMirrorWindow::debugLog(const QString& s) {
      if (g_self) g_self->dumpDebug(s);   // 只判非空，不判对象是否已销毁
  ```
  而 `debugLog` 由**进程级** `s_pollTimer`（150ms）、`guardEventProc`（全局事件钩子）、`topmostAllTargets` 等调用，这些调用源的存活期可能长于窗口。
- **为何当前不崩**：`dumpDebug()`（`:3441-3445`）是**空实现**（`Q_UNUSED(tag)`），函数体不访问 `this`，所以"传悬垂 this"暂时无害。
- **风险**：这是一颗**定时炸弹** —— 一旦 `dumpDebug` 恢复任何成员访问，立即变致命。
- **为何不是本次根因**：正因为是空实现，不会崩。

### ② 🟡 `s_cloakTargets` 的 HWND 键残留（HWND 复用 → 误操作他人窗口）

- **位置**：`desktopmirrorwindow.cpp:362`（`QHash<HWND, QPointer<QWidget>>`）
- **问题**：`unregisterCloakTarget()`（`:627-630`）存在且正确，但 **`stopMirror()`（`:336-347`）与析构路径均未调用它** —— 图标按钮被销毁后，HWND 键永久残留。
- **后果**：值虽是 `QPointer`（**不会** use-after-free），但**键**会被 Windows 回收复用。届时 `isProtectedWindow()`（`:607`）对**别人的窗口**返回 `true`，`guardEventProc`（全局钩子）会对其执行 `SetWindowPos(HWND_TOPMOST|SWP_SHOWWINDOW)`。
- **触发条件**：长时间运行 + Explorer 重启 / 大量窗口创建销毁。
- **为何不是本次根因**：不导致崩溃，最多是行为异常。

### ③ 🟡 `relayoutFences()` 无上限的 0ms 自重排

- **位置**：`icongridwindow.cpp:2717-2724`
  ```cpp
  if (m_fencesContainer->width() <= 0 || m_fencesContainer->height() <= 0) {
      QTimer::singleShot(0, this, &IconGridWindow::relayoutFences);   // ⚠ 无重试上限
      return;
  }
  ```
- **后果**：只要容器尺寸持续为 0（窗口隐藏/折叠/几何未就绪），就**每次事件循环都再投一个 0ms 定时器**，GUI 线程空转、CPU 占用拉满 —— 用户观感就是"卡死"。
- **为何不是本次根因**：是 CPU 占用问题，不产生退出。

### ④ 🟡 两处静态缓存无上限（内存单调增长）

| 位置 | 缓存 | 清空条件 | 对照 |
|---|---|---|---|
| `desktopscanner.cpp:379` | `static QHash<QString, QIcon> g_iconCache` | **仅**用户手动切"显示快捷方式箭头"开关时 | 同文件 `isRealShortcut` 缓存（`:915`）**有** `if (cache.size() > 512) cache.clear();` |
| `desktopscanner.cpp:545` | `static QHash<QString, QString> cache`（`effectiveTarget`） | **无任何清空** | 同上，独独漏了 |

- **额外开销**：`effectiveTarget` 每次调用都做一次 `QFileInfo(sourcePath)`（**磁盘 stat**），键含 mtime → 改名/保存即产生新键，只增不减。
- **为何不是本次根因**：程序是 **64 位**（PE32+=x64，已核验），地址空间远未触及；且 `g_iconCache` 键数量受桌面项数约束（当前 216 项），1 小时不足以耗尽内存。

### ⑤ 🟡 菜单动作按**文本**匹配 `"退出"` → 静默退出

- **位置**：`mainwindow.cpp:1849-1851`
  ```cpp
  } else if (text == QStringLiteral("退出")) {
      qApp->quit();
  ```
- **问题**：该分支所在的分发函数处理的文本包含**用户自定义的分类名**；而保留名检查（`icongridwindow.cpp:1321-1325`）**只保留 `"系统"`**。
  → 用户完全可以建一个名为**「退出」**的分类，点击其菜单项即**无任何日志地退出程序**。
- **现状**：**已核验当前 `categories.ini` 不含"退出"二字，本次未命中。**
- **建议**：改为 `QAction*` 指针比较（侧栏 `sidepanelwidget.cpp:1025` 已是正确写法，可照抄），并把「退出」加入保留分类名。

### ⑥ 🟢 若干单次性资源未回收（不随时间累积）

| 项 | 位置 | 说明 |
|---|---|---|
| 4 个 `SetWinEventHook` 无 `UnhookWinEvent` | `desktopmirrorwindow.cpp:679/684/689/694` | 有 `if (!s_cloakHook)` 守卫，**各注册一次**，非累积 |
| `RegisterShellHookWindow` 无 `DeregisterShellHookWindow` | `mainwindow.cpp:348` | 同样只注册一次 |
| `FileSearchWidget` 的 worker 未 `delete` | `filesearchwidget.cpp:47-48` / 析构 `:91-95` | 每次开搜索窗漏一个；无 parent，析构只 quit/wait 线程 |
| `refresh()` 500ms 无限自重排 | `desktopmirrorwindow.cpp:837-839` | 条件为"列表未就绪"，正常情况很快退出 |

### 已核对为「干净」的项目（无泄漏）

> 为免误解，以下均**逐分支核对无泄漏**：
> - **GDI**：`GetDC/ReleaseDC`、`CreateCompatibleDC/DeleteDC`、`CreateCompatibleBitmap/DeleteObject`、`SelectObject` 还原 —— 截图代码 `settingcenterdialog.cpp:1690-1705` 完整配对
> - **HICON**：`SHGetImageList` / `SHDefExtractIcon` / `IExtractIcon` / `SHGetStockIconInfo` / `ExtractIconEx` / `SHGetFileInfo` 全部成对 `DestroyIcon`
> - **内核句柄**：`OpenProcess`、`CreateFileW`、`VirtualAllocEx`、`RegOpenKeyEx` 全部路径释放
> - **COM**：`IShellFolder` / `IEnumIDList` / `IContextMenu` / `IShellLinkW` / `IImageList` 的 `Release()` 与 `CoTaskMemFree` 齐全
> - **Qt**：分类页缓存有 `qBound(8,size,24)` 上限 + LRU；图标队列只减不增；`ThemeManager::m_targets` 有回收；**无常驻 <50ms 定时器**；**无跨线程访问 QWidget**

### 7.2 建议新增的「退出原因留痕」（低风险、高收益）

当前证据的短板是：**无法区分"正常退出"和"被强杀"**。建议在 `main()` 里加一行 —— 利用 Qt 的 `aboutToQuit` 信号，在**一切正常退出路径上**写一条记录到 `DestopTools_crash.log`：

```cpp

    CrashTrace::mark("normal-quit");   // 复用现有零分配接口
});
```

这样下次若再"消失"：
- 日志里有 `normal-quit` → **是显式 quit**（配合时间戳可定位是哪条出口）
- 日志里**没有** → **被外部终止**（TerminateProcess 不会触发 `aboutToQuit`）

**成本**：1 处改动、约 3 行；**不动任何既有功能**。
