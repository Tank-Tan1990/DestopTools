# 分区标签切换：悬停模式补「选中态」同步

- 日期：2026-09-22 00:14
- 需求（用户原话）：「悬停切换时，请顺便把选中状态也进行切换了」
- 影响文件：`DestopTools/icongridwindow.h`、`DestopTools/icongridwindow.cpp`（仅 1 个新函数 + 1 处调用，其它逻辑未动）
- 产物：`DestopTools/release/DestopTools.exe`（**1259008 B @ 2026-09-22 00:12:20**，NMAKE_EXIT=0）

## 一、根因

分类标签的创建方式是：

```cpp
btn->setCheckable(true);
btn->setAutoExclusive(true);
```

于是 **「点击切换」下那个高亮框根本不是我们代码设的，而是「点击」这个动作的副作用** ——
Qt 在 `mouseReleaseEvent → QAbstractButtonPrivate::click() → nextCheckState()` 里自动把被点的按钮置为选中，
并互斥地取消同父兄弟。历史实现只挂 `clicked`，高亮就这样"顺带"对了。

`activateCategoryTab()` 是点击/悬停共用入口，但**它从来没有设过选中态**；悬停切换没有点击这一步 →
分类内容、徽标标题都换了，唯独标签高亮留在旧标签上。用户看到的就是「悬停切换了，选中框没跟着切」。

## 二、改动

新增 `IconGridWindow::syncCategoryTabChecked(QToolButton* target)`，并在 `activateCategoryTab()` 首句调用：

```cpp
void IconGridWindow::activateCategoryTab(QToolButton* btn) {
    if (!btn) return;
    const QString cat = ...;
    if (cat.isEmpty()) return;
    syncCategoryTabChecked(btn);   // ← 新增：点击路径幂等，悬停路径靠它把高亮带过来
    m_currentCategory = cat;
    ...
}
```

同步顺序（不依赖 Qt 隐式互斥的实现细节，跑完保证**恰好一个**标签被选中，且就是当前分类那个）：

1. 目标未选中 → `setChecked(true)`（`autoExclusive` 会顺带取消兄弟）；
2. 再扫一遍标签栏，兜底清掉漏网兄弟；若某个 `autoExclusive` 按钮拒绝被直接取消，
   就临时 `setAutoExclusive(false)` → `setChecked(false)` → **原样恢复**（只在该帧内生效，不改变外部语义）。
