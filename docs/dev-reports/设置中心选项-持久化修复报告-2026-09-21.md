## 一、用户报的现象

> 「红框中的选项框的开启/关闭，之前的本地化持久数据是好的，现在坏了」
> 「开启/关闭，为什么没有入本地持久化数据」

即：外观设置页「分区标签切换 = 点击切换 / 悬停切换」的选中状态重启后不保留，看着像"没写进本地配置"。

## 二、结论（先说答案）

**写盘从来没问题，坏的是"读回来"。**
磁盘里明明存着 `Appearance/tagSwitchMode=1`（悬停切换），重新打开设置中心却是**两个单选钮都没选中**。

根因：**同一父窗口下的 4 个 `QRadioButton` 被 Qt 自动合并成【一个】互斥组**。
外观设置页上有**两对**单选钮：

| 分组 | 按钮 |
|---|---|
| 分区标签切换 | 点击切换 / 悬停切换 |
| 分区菜单标签显示 | 始终显示 / 鼠标悬停显示 |

它们都是同一个页面 widget 的兄弟节点，于是被 `autoExclusive` 机制并成**同一组**。`loadSettings()` 先给"分区标签切换"赋值、再给"分区菜单标签显示"赋值，**后一对会把前一对刚选中的踩掉**：

```
2198: clickR->setChecked(tagSwitchMode == 0)   // ①
2199: hoverR->setChecked(tagSwitchMode == 1)   // ② hoverR 选中，同时把同组的「始终显示」清掉
2200: alwaysR->setChecked(menuLabelShow == 0)  // ③ 重新选中「始终显示」→ 把 ② 刚选中的 hoverR 清掉
2201: mhoverR->setChecked(menuLabelShow == 1)  // ④
⇒ 结果：点击[0] 悬停[0] —— 存了 1 也显示不出来
```

## 四、改动（只改这一处）

`settingcenterdialog.cpp` → `createAppearancePage()`，在两对单选钮创建完之后各装一个 `QButtonGroup`：

```cpp
// 🚨 两对单选钮必须【各自】装进 QButtonGroup，否则本页 4 个 QRadioButton 是同一父窗口的
//    兄弟节点，会被 Qt 的 autoExclusive 合并成一个互斥组 —— 于是 loadSettings() 里后赋值的
//    那对会把先赋值的那对刚选中的踩掉，表现就是「磁盘存了 1、重开设置中心两个都没选中」。
if (auto* g = new QButtonGroup(this)) {
    g->addButton(m_tagClickRadio, 0);
    g->addButton(m_tagHoverRadio, 1);
}
if (auto* g = new QButtonGroup(this)) {
    g->addButton(m_menuAlwaysShowRadio, 0);
    g->addButton(m_menuHoverShowRadio, 1);
}
```

**副作用（顺带修好的）**：修复前点「悬停切换」会**悄悄把「始终显示」清掉**（反向同理），
也就是两对设置互相破坏；装组之后不再互相影响。

## 七、方法论教训（已写进项目铁律）

**试验台脚本必须在构建前删掉自己的 exe，强制重新链接产品 .obj。**
试验台 `.pro` 用 `$$files(release/*.obj)` 静态链入产品对象，但 nmake 的依赖规则里只有 `main.obj` ——
**产品重编后若试验台源码没动，nmake 会跳过链接**，跑的就还是上一次的产品代码。
本轮就因此把已修好的版本误判为"仍未修复"（第一次复测 `scprobe.exe` 23:48:08 早于修复后的 `settingcenterdialog.obj` 23:49:02）。
`tools/run_*.py` 共 10 个脚本已全部补上这段强制重链。

## 八、回退点

删掉 `createAppearancePage()` 里新增的两个 `QButtonGroup` 代码块，即回到改动前行为（无其它改动）。
