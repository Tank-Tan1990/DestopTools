## 一、F2 / Delete / 重命名 全废 —— 根因：A1 的"持钩闸门"判据用错

**这是一条可完整推导、100% 确定的缺陷链，不是猜测。**

### 证据链

1. 两侧的持钩闸门分别是 `DesktopMirrorWindow::s_hkActive` 与 `IconGridWindow::s_gridHooksActive`；
   `IconGridWindow::hotkeyGateOk()` 的**第一句**就是（`icongridwindow.cpp:680`）：

   ```cpp
   if (!s_gridHooksActive) { ...return false; }   // ← 为假则 F2/Delete 全废
   ```

2. A1 把两套独立钩子合并成了一个**全进程共享**的钩子对，`suspend()/resume()` 用的是**全进程嵌套计数**
   `m_suspendDepth`；而两侧的 suspend/resume 是**分别**调用的。

3. `mainwindow.cpp` 有三处成对调用（启动 2.5s 兜底重扫 `287-299`、析构 `353-379`、`refreshDesktop`），
   顺序**统一**为：

   ```
   suspendHotkeyHooks()   → Dock 计数 0→1；管理器 0→1（摘钩）
   suspendGridHooks()     → Grid 计数 0→1；管理器 1→2（已摘，提前返回）
   ... 重活 ...
   resumeGridHooks()      → Grid 计数 1→0；管理器 2→1 ⇒ 非 0 ⇒ reinstall() 被跳过（钩子仍未装）
   resumeHotkeyHooks()    → Dock 计数 1→0；管理器 1→0 ⇒ reinstall() 真正装回
   ```

4. 旧的 `ensureGridHooks()` 里是 `s_gridHooksActive = lowLevelHooks().active();`。
   在 `resumeGridHooks()` 那一刻，管理器计数仍是 1（Dock 还没 resume）→ `active()` 返回 **false**
   → **收纳盒把自己的闸门清成 false**，而此后**没有任何路径会把它改回 true**（`resumeHotkeyHooks`
   只刷新 Dock 自己的；`ensureGridHooks` 只在下一次交互时才被调用）。

5. 结果：**启动约 2.5 秒后，收纳盒内的 F2 / Delete / 重命名 全部静默失效**，直到用户在收纳盒里
   再点一下（`armGridHotkey → registerGridWindow → ensureGridHooks`）才恢复 —— 表现为"时灵时不灵"。
   Dock 侧同理会中招（取决于哪一侧先 resume）。

### 修复（判据与暂态摘钩解耦）

| 位置 | 改动 |
|---|---|
| `lowlevelhookmanager.h` | **新增** `bool registered(const void* token)`：只回答"我还在注册名单里吗"，与"此刻句柄是否在位"无关 |
| `desktopmirrorwindow.cpp:ensureHotkeyHooks()` | `s_hkActive = lowLevelHooks().registered(this)`（原为 `active()`）；并只在注册成功时认领 `s_hkOwner` |
| `icongridwindow.cpp:ensureGridHooks()` | `s_gridHooksActive = lowLevelHooks().registered(&s_gridWindows)` |

**为什么闸门不该看 `active()`**：摘钩期间（重活中）根本收不到任何按键，闸门真假无意义；
而"我还在名单里"才是恢复后能否响应的正确依据。摘钩 → 装回后，两侧闸门都保持 true，无需互相通知。

## 二、Win+D / Win+M 三窗可见性 —— 根因：B1 的"跳过 DWM 探测"门控 + A2 缓存的两处缺口

### 2.1 B1 的探测门控（决定性错误）

上一轮把 `restoreAllTargets()` 的兜底探测改成：

```cpp
const bool probeAlways = s_desktopActive || (s_pollCount % 5 == 0);
DWORD cloaked = 0;
if (probeAlways || iconic || hidden) { DwmGetWindowAttribute(..., kDwmwaCloaked, &cloaked, ...); }
...
if (hidden || cloaked) { /* 去掉遮蔽 + ShowWindow 重新点亮 */ }
```

**错在前提假设**：注释里写的"外壳隐藏必然同时让窗口变为不可见或最小化"**不成立**。
**DWM 遮蔽（DWMWA_CLOAKED）恰恰不改变 `WS_VISIBLE`** —— 被遮蔽掉的窗口 `IsWindowVisible()` 仍为 TRUE、
`IsIconic()` 也为 FALSE。于是"跳过探测"的那 4 拍里 `cloaked` 恒为 0 → `hidden || cloaked` 判假
→ 该窗口一直不被重新点亮。Win+D / 显示桌面退出后即表现为收纳盒/助手"不见了"。

**修复**：恢复**每拍都探测**（`if` 门控整体删除，`hr = DwmGetWindowAttribute(...)` 无条件执行）。
节流收益主要来自**把间隔从 50ms 放大到 150ms**（探测次数 60 次/秒 → 6.7 次/秒，降 9 倍），
而不是"跳过探测"。

### 2.2 A2 分类缓存的两处缺口（同样能导致三窗被显示桌面隐藏）

1. **HWND 复用**：缓存只以 `HWND` 为键。HWND 会被系统复用（内联重命名编辑框、临时收纳盒这类
   快速创建/销毁的窗口极可能拿到刚释放的句柄值），新窗口会**继承旧窗口的分类**。
   若一个复用了"普通顶层窗/子控件"句柄的**新收纳盒**被判成非挂件 → 它拿不到
   `WS_EX_TOOLWINDOW`、也清不掉 `WS_EX_APPWINDOW` → **显示桌面/Win+D/Win+M 就能隐藏它**。
2. **"免疫只做一次"**：桌面挂件的 EX 样式一旦因任何原因（分类瞬间的时序、外壳或第三方工具改写、
   explorer 重启）不正确，**没有任何机制改回来**。
   另外 `WM_DESTROY` 清缓存的假设也不完全成立（同线程 `DestroyWindow` 是**直发**消息，
   未必经过消息队列 → 全局 native event filter 可能看不到），陈旧条目可能留存。

**修复**（`desktopimmunityfilter.h/.cpp`）：

| 改动 | 说明 |
|---|---|
| 缓存增加"身份"校验 | 新增 `m_kindWidget`（HWND → 当时 `QWidget::find(hwnd)` 的指针）。命中时比对身份，**不一致即丢弃全部陈旧状态并重新判定**。代价只是一次 QHash 查找，零系统调用 |
| 认不出的窗口**不缓存** | 若该 HWND 已建好但 Qt 侧 WId→QWidget 映射尚未登记（`QWidget::find` 返回空），**当条消息不干预且不写缓存**。否则若它其实是内联重命名编辑框，会被加上 `WS_EX_NOACTIVATE` → 永远拿不到键盘焦点（打不进字）——正是 2026-09-13 那类缺陷的复现路径 |
| 免疫样式改为**周期自愈** | EX 样式断言移入 300ms 节流复核块内：**每次复核都重新断言** `WS_EX_NOACTIVATE\|WS_EX_TOOLWINDOW` 且清 `WS_EX_APPWINDOW`。常态样式相符时只是 1 次 `GetWindowLongPtrW`，开销可忽略；最坏 300ms 内自愈 |
| `KindExternal` 不再缓存 | 本进程过滤器几乎见不到外部窗口消息，缓存它只会引入"外部句柄被复用成本进程窗口"的误判面 |
| 纵深防御 | `KindPlainTopLevel` 在写 `WS_EX_NOACTIVATE` 前**再验一次** `isInputWidget()`（命中则升级为 `KindInput`）。只对自家普通顶层窗（数量个位数）付这份代价，全屏 Dock 走挂件分支不受影响 |

### 2.3 B2 的"不可见即跳过"已撤回

`parkAllTargetsAtBottom()` 同时是 `exitDesktop()/untopmostAllTargets()` 的 z 序复位通道。
若此刻 Dock 恰好处于"被外壳 SW_HIDE 但尚未被 `restoreAllTargets` 复活"的窗口期，
跳过会让 Dock 复活后停在其它程序之上（历史"遮挡其它程序"缺陷）。恢复原"无条件压底"语义，
只保留 3s 周期（1 次 SetWindowPos / 3s，可忽略）。

## 三、同时回退 A3（"点编辑框外即提交"守卫）

上一轮把 `qApp->installEventFilter(this)` 从常驻改成"仅编辑期挂载"，卸载判据是
"遍历 `m_buttons` 确认无人处于编辑态"。但 `m_buttons` 在刷新/重建窗口期可能**瞬时不含**
正在编辑的按钮 → 过滤器被提前摘掉 → **"鼠标点编辑框外即提交"失效**。
该守卫是内联重命名唯一的鼠标兜底通道，**可靠性优先**：恢复构造期常驻挂载。

> 这一项只值一次虚调用/事件，是全清单里收益最小的一项，代价却是核心功能失效，不值得。
