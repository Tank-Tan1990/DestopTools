## 一、机理（为什么以前会卡）

本程序此前装了系统级低级鼠标钩子 `WH_MOUSE_LL`。Windows 对低级钩子的规定是：
**每一次鼠标移动都必须同步回调进安装线程（= 我们的 GUI 线程）并等它返回**，才把输入继续往下发。
1000Hz 鼠标 = 每秒最多 1000 次这样的往返。于是只要 GUI 线程有一刻不空闲（重绘、布局、
图标提取、跨进程查询……），**整个系统的光标都要等我们**。

所以优化的靶子不是"回调里写了什么"，而是两件事：
**① 不再让系统等我们；② 少占用 GUI 线程。**

## 二、已做的改动

### #1 🎯 根治：鼠标钩子 → Raw Input

**新增 `rawmouse.h`（header-only）**：自建一个**隐藏顶层窗口**（`WS_POPUP` + `WS_EX_TOOLWINDOW|NOACTIVATE`，
从不 Show），注册鼠标设备时用 **`RIDEV_INPUTSINK`**（窗口不在前台也照样收 —— Dock 是
`WS_EX_NOACTIVATE`，永远不会是前台窗口，所以 INPUTSINK 是本方案的前提），然后在 `WM_INPUT` 里：

1. 先 `GetRawInputData` 读 `usButtonFlags` —— **纯移动立即返回**（最常见路径，一次 ~1µs 内核拷贝，不做别的）；
2. 只有真有按键时才 `GetCursorPos()` 取位置，把它塞进一个 `MSLLHOOKSTRUCT` 分发出去。

> **关键收益**：Raw Input 是**异步投递**。我们处理得慢只会堆积在自己的消息队列里，
> **绝不会阻塞系统输入链** —— 别人拖鼠标、你在别的程序里操作，永远不受本程序影响。
> 这是与钩子的本质区别，不是"优化一点"，而是"换掉机制"。

**消费者代码零改动**：因为载体仍是 `MSLLHOOKSTRUCT`（`ms->pt`），Dock 的 `hotkeyMouseConsumer`
与收纳盒的 `gridMouseConsumer` 一行没改。`LowLevelHookManager` 内部把鼠标分发接到 Raw Input，
对外接口（`subscribe/suspend/resume/registered`）与语义完全不变。

**键盘仍用 `WH_KEYBOARD_LL`**：F2 / Delete 需要"**吞键**"（阻止下传到前台程序），Raw Input 只能观察不能拦。

**两道安全网（必须有）**：
1. **注册失败 → 自动降级**：`RegisterRawInputDevices` 失败时立刻回装 `WH_MOUSE_LL`，功能与改造前一致。
2. **🚨 注册成功但消息送不到 → 交叉验证后降级**：这是最危险的情形（会被安全软件/沙箱静默拦掉，
   表现是 F2 / Delete / 框选 / 双击**全部无声失效**）。判据不是"N 秒内没收到就降级"（那会在
   "开机自启后你半天没碰鼠标"时误判），而是**交叉验证**：`DesktopImmunityFilter` 只要看到一个真实的
   `WM_MOUSEMOVE`（说明系统正在正常投递鼠标消息给我们的 Qt 窗口），而 Raw Input 注册满 1.5 秒后
   仍是 **0 条**，就判定通道在本机不通 → 立刻降级回 `WH_MOUSE_LL`。

**本机实测（`tools/rawinput_selftest.py`，与 rawmouse.h 同构的独立验证）**：
```
sink hwnd = 0x470426 (hidden, never shown)
RegisterRawInputDevices OK (RIDEV_INPUTSINK)
phase1 (passive 6s): WM_INPUT=0 buttons=0
no event seen -> inject zero-delta move (MOUSEEVENTF_MOVE,0,0)
phase2 (after inject): WM_INPUT=1
RESULT: RAW INPUT CHANNEL OK
```
→ 隐藏窗口 + INPUTSINK 在本机确实收得到 `WM_INPUT`，通道成立。
（阶段 1 为 0 恰好说明为什么要做阶段 2：被动等待会被"用户刚好没动鼠标"骗到。）

### #4 鼠标类消息在消息过滤器里直接早退
`desktopimmunityfilter.cpp`：`WM_MOUSEMOVE / WM_NCHITTEST / WM_SETCURSOR / WM_MOUSEWHEEL /
WM_MOUSELEAVE / 各类按键` + **`WM_INPUT`** 一律 `return false`，免掉每条消息一次
`QWidget::find` + 2~3 次 QHash 查找。
> ⚠️ 其中 `WM_INPUT` 这条是**必须的**：Raw Input 的每条消息也会先经过 Qt 的消息过滤器，
> 不过滤的话每秒上千条 × 2 次系统调用，会把 Raw Input 的收益当场吃光。

### #5 喇叭闪烁：去掉 effect + 无限动画
`sidepanelwidget.cpp`：原实现是 `QGraphicsOpacityEffect` + `QPropertyAnimation` **无限循环**。
effect 是**离屏渲染**（每帧把部件渲染进 pixmap 再整体合成），只要有未确认的提醒就 60fps 常驻跑。
现改为**预渲染两版位图 + 450ms 定时器互换**（一明一暗 = 900ms，与原节奏一致）：
每 450ms 只有一次 `setPixmap`（14×14 小图），且面板不可见时不重绘。
> 🚨 踩过的坑：预渲染第二帧时**不能先给目标 pixmap 设 DPR 再画** —— 那样源图的逻辑尺寸会参与
> 坐标变换，非 1.0 缩放下只画到左上角 1/4。改用"源/目标矩形都用设备像素"的写法，与 DPR 解耦。

### #7 图标队列：每拍 2 个 → 1 个
`desktopiconbutton.cpp`：单拍阻塞上限从 ≈40ms 降到 ≈20ms（GUI 线程同时要回调钩子，
单拍阻塞直接等于"全系统鼠标瞬时迟滞"）。代价只是整屏图标铺满略慢（每个 30ms）。

### #8 全局事件钩子加归属闸门 + 删诊断块
`desktopmirrorwindow.cpp`：
- 4 个 `SetWinEventHook` 是**全局范围**安装的，系统里任何窗口的显示/隐藏/最小化都会回调进来
  （`EVENT_OBJECT_SHOW` 尤其高频）。现在 `guardEventProc` 第一行就是 `isProtectedWindow(hwnd)`
  归属判定（O(1) 查表），非本程序受保护窗口立即返回。
- 删掉原"每 200 个事件构造一次诊断字符串"的块（`dumpDebug` 早已是空函数，参数却照旧构造）。

### #2 常驻轮询减负（**未降频**，只降单次成本）
`s_pollTimer` 的 150ms 周期**保留**，但把每次 tick 的成本压下来：
- 删掉"每 50 拍（≈7.5s）打印全部受保护窗口真实状态"的诊断块 —— 它每次对每个窗口做
  **跨进程** `DwmGetWindowAttribute` + 构造长 QString，而出口是空函数；
- `isForegroundRealApp()` 去掉 `QString::fromWCharArray` 堆分配，改 `wcsstr` 宽字符比较。
> **为什么不降频到 1s**：这个轮询负责"前台切回真实程序 → 撤下 topmost"的边沿动作，
> 延迟 1 秒会让三窗口最多遮挡别的程序 1 秒（历史上正是"遮挡其它程序"这类缺陷）。
> 单次成本已降到微秒级，保留 150ms 更稳。

## 三、复核后**没做**的两项（请你判断是否需要坚持）

| # | 原提议 | 为什么没做 |
|---|---|---|
| **#3** | 每 3 秒给窗口 `SetWindowPos(HWND_BOTTOM)` 改为"先比对 z 序" | ①它**只压 Dock 一个窗口**（不是三个），3s/次单次调用成本可忽略；②判据不可靠 —— Dock 之下还有桌面窗口（WorkerW/Progman），`GW_HWNDPREV` 无法表达"应该在哪"；③**源码注释里明确记录过**：曾经加过"看起来没必要就跳过"，结果造成"Dock 复活后停在其它程序之上（遮挡）"的历史缺陷，所以当时是**刻意**保留无条件压底的。收益 ≪ 风险 |
| **#9** | 5 个弹窗的 1s 层保持改为"按需纠偏" | 只在这些窗口**打开时**才跑，且 `assertLayerAboveBandWindows` 内部已有 `if (!isVisible()) return`。要真正按需就得重写 `raiseAboveBandWindows` 的 z 序判定，而那是"弹框被收纳盒盖住"这类历史缺陷的所在。收益中等、风险中等，不建议动 |

**#6（桌面刷新全量重建）复核结论：已经是优化过的** —— `refresh()` 里早有一段 SHA1 内容指纹
（涵盖 displayName / shellPath / special / hasPos / screenPos / lvIndex / iconSizePx 七项），
条目未变时直接 `return`，不重建按钮、不清选中。所以此条**无需改动**。
