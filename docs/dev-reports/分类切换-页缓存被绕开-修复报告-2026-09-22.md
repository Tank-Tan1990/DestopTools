# 分类切换「多切几次还是能看到刷新」— 修复报告

- 日期：2026-09-22
- 触发：用户反馈「没有处理到位，多切换几次，还是能看到刷新」
- 改动文件：`DestopTools/icongridwindow.h`、`DestopTools/icongridwindow.cpp`
- 产物：`DestopTools/release/DestopTools.exe` = **1,270,784 B @ 2026-09-22 01:28:19**（较上轮 +1536 B），`NMAKE_EXIT=0`

## 一、结论先说

上一轮的「分类页缓存」机制本身是好的，但**有两条路径会把它绕开或当场销毁**。只要多切几次、
或满足其中任一条件，缓存就等于不存在 → 每次切换都在重建按钮，现象就是"还是能看到刷新"。

| # | 根因 | 何时被触发 | 后果 |
|---|------|-----------|------|
| 1 | `resizeEvent()` / `showEvent()` 在列数变化时调 `rebuildGrid()` | 切换分类 → 内容多少变 → 滚动条出现/消失 → 视口宽度变 → 列数变 | `rebuildGrid()` 开头 `invalidateCategoryPages()` **销毁全部缓存页** |
| 2 | `setSearchText()` 无条件 `rebuildGrid()`，而切换分类会经助手面板 `clearSearch()` 回调它 | 助手面板搜索框里**有字**时每次切换必中 | 同上，且切换内还会**双重建**（先建、再被 discard、再建） |

根因 1 解释了"**多切几次**才看出来"：只有滚动条状态与上一次不同的那几次切换才会撞上，来回切两个
图标数不同的分类必然周期性命中。

## 二、根因 1：几何抖动被当成"数据变了"

`IconGridWindow::resizeEvent()`（修复前）：

```cpp
} else if (!m_boxView) {
    if (m_viewMode == ViewList) {
        if (listRowWidth() != m_listRowWidth) {
            QTimer::singleShot(0, this, [this]() { rebuildGrid(); });   // ← 元凶
        }
    } else if (computeGridColumns() != m_actualGridCols) {
        QTimer::singleShot(0, this, [this]() { rebuildGrid(); });       // ← 元凶
    }
}
```

`rebuildGrid()` 的第一件事就是：

```cpp
invalidateCategoryPages();   // 代次 +1，销毁全部分类页缓存
```

于是链路闭合：

```
切到另一个分类
  → 网格内容数量变
  → 竖向滚动条出现 / 消失
  → m_gridScroll->viewport() 宽度变
  → computeGridColumns() 与 m_actualGridCols 不等
  → resizeEvent 排队 rebuildGrid()
  → invalidateCategoryPages()
  → 刚 park 进缓存的页全部销毁
  → 下次切回该分类 = 重建（用户看到的"刷新"）
```

`showEvent()` 里那句 `QTimer::singleShot(0, this, [this]() { rebuildGrid(); })`（首屏几何就绪后重排列数）
同理，每次窗口显示都会毁一次缓存。

**关键认识**：几何变化（窗口缩放、滚动条出现/消失）**不需要重建按钮**。
除列表档外，按钮尺寸只由「查看」档位决定（大/中/小），与列数无关；列数变了只是"该怎么摆"变了。
既然只需重排，就不该走会作废缓存的重建路径。

## 三、根因 2：搜索框回环（有字时每次切换必中）

`activateCategoryTab()` 里的 `emit categoryChanged(cat)` 触发了这条链：

```
IconGridWindow::activateCategoryTab()
  → emit categoryChanged(cat)
      → MainWindow::onCategoryChanged()
          → m_assistantWindow->panel()->clearSearch()
              → QLineEdit::clear()  →  emit textChanged("")
                  → MainWindow::onSearchChanged("")
                      → IconGridWindow::setSearchText("")
                          → rebuildGrid()          ← 又一句 invalidateCategoryPages()
```

而此刻切换流程**自己早已** `m_searchText.clear()` 并准备好换页了 —— 这次回调纯属重复，
却把刚 `park` 好的缓存全毁了。更糟的是 `emit` 发生在 `switchCategoryPage()` **之前**，于是还会：

1. 回调里先按新分类 `applyGridItems()` 建一遍；
2. 回到 `switchCategoryPage()` → `parkOld=false` → `discardCurrentGridPage()` 把刚建的**销毁**；
3. 再 `adoptCachedGridPage()`（缓存已空）→ 又 `applyGridItems()` 建一遍。

**一次切换重建两遍。**

## 四、修法（4 处，均在 `icongridwindow.h/.cpp`）

### 1. 新增 `relayoutGridForGeometry()` —— 几何变化的唯一出口

```cpp
void IconGridWindow::relayoutGridForGeometry() {
    if (!m_gridLayout) return;
    if (m_menuOpen || isEditingAnyIcon() || m_iconDragInProgress) { m_pendingRebuild = true; return; }
    if (m_fencesMode || m_boxView) return;
    if (m_gridScroll && m_gridScroll->widget() != m_gridContainer) return;
    if (!m_gridScroll || !m_gridScroll->viewport() || m_gridScroll->viewport()->width() <= 0) return;

    QVector<DesktopIconButton*> btns;                       // 收集布局里**现有**按钮
    for (int i = 0; i < m_gridLayout->count(); ++i)
        if (QLayoutItem* it = m_gridLayout->itemAt(i))
            if (auto* b = qobject_cast<DesktopIconButton*>(it->widget())) btns.append(b);

    const QVector<DesktopItem> items = currentItems();
    if (btns.size() != items.size()) { rebuildGrid(); return; }   // 数据已变 → 交给全量路径
    if (btns.isEmpty()) return;

    const GridMetrics gm = prepareGridLayout(items);        // 刷新 m_actualGridCols / m_listRowWidth
    for (DesktopIconButton* b : btns) { b->setListMode(gm.listMode); b->setViewMetrics(gm.iconW, gm.iconH, gm.iconPx); }

    while (m_gridLayout->count()) {                          // 摘下（只删 item，不删按钮）
        QLayoutItem* it = m_gridLayout->takeAt(0);
        if (!it) continue;
        if (it->widget() && !qobject_cast<DesktopIconButton*>(it->widget())) it->widget()->deleteLater();
        delete it;
    }
    for (int i = 0; i < btns.size(); ++i)                    // 按新列数放回
        m_gridLayout->addWidget(btns[i], i / gm.cols, i % gm.cols, Qt::AlignTop | Qt::AlignLeft);
}
```

- `resizeEvent()` 两处、`showEvent()` 一处，全部由 `rebuildGrid()` 改调它。
- 缓存页、图标位图、信号连接**全程原地不动**；当前页也不重建，只是重新摆位。
- 只有"现有按钮数 ≠ 当前条目数"（说明数据变了但还没重建）才退回 `rebuildGrid()`。

### 2. `setSearchText()` 早退，断掉回环

```cpp
void IconGridWindow::setSearchText(const QString& text) {
    const QString t = text.trimmed();
    if (t == m_searchText) return;      // ← 新增：切换分类经 clearSearch 回调时，文本已空，直接返回
    m_searchText = t;
    rebuildGrid(false);                 // ← 搜索进/出不改任何分类条目 → 不作废分类页缓存
}
```

### 3. `adoptCachedGridPage()` 不再拿"列表档行宽"当命中判据

行宽会随滚动条出现/消失抖动，据此丢弃缓存等于"切回来仍重建"。改为**装回后按当前度量重设尺寸**：

```cpp
if (page.generation != m_pageGeneration || page.viewMode != m_viewMode) { /* 丢弃重建 */ }
...
b->setListMode(m.listMode);
b->setViewMetrics(m.iconW, m.iconH, m.iconPx);   // DesktopIconButton 内 px 未变时早退，近零成本
m_gridLayout->addWidget(b, i / m.cols, i % m.cols, Qt::AlignTop | Qt::AlignLeft);
b->show();
```

### 4. `rebuildGrid(bool invalidatePages = true)`

只有"搜索框进/出"这类不改任何分类条目的纯视图变化传 `false`；其余数据路径保持默认 `true`（缓存必须作废）。
⚠️ 签名带参后 `QTimer::singleShot(0, this, &IconGridWindow::rebuildGrid)` 无法推导 → 3 处 member-pointer
调用已全部改为 lambda。

## 五、修复后的切换时序（网格视图、点击标签 B、当前显示 A）

```
activateCategoryTab(btnB)
 ├─ syncCategoryTabChecked(btnB)        → 高亮跟上（悬停/点击一致）
 ├─ cat != m_currentCategory （相同则直接 return）
 ├─ m_currentCategory = B / m_searchText.clear() / saveCurrentCategory()
 ├─ emit categoryChanged(B)
 │    └─ panel->clearSearch() → textChanged("") → setSearchText("")
 │         └─ t("") == m_searchText("") → **早退**，不 rebuildGrid ✅
 └─ switchCategoryPage(A → B)
      ├─ parkCurrentGridPage(A)         → A 的按钮换父到隐藏宿主保活，登记入缓存
      ├─ prepareGridLayout(currentItems()) → 刷新列数/行宽（布局参数与装回共用）
      └─ adoptCachedGridPage(B)
           ├─ 命中 → 按当前列数 addWidget 装回 + show()      → 零重建 ✅
           └─ 未命中 → applyGridItems() 首次构建
（此后滚动条出现/消失导致的 resizeEvent → relayoutGridForGeometry() → 只重排，缓存不受影响 ✅）
```

## 七、请实测的点

1. 依次点开 3~4 个分类，再**来回切换多次**——切回看过的分类应**立即出现**，无重建闪烁。
2. 大小差别明显的分类之间来回切（如 3 个图标 vs 40 个图标，滚动条反复出现/消失）——这是原先必现的场景。
3. 在助手面板搜索框**输入文字**后切分类，再清空搜索来回切——原先每次必重建的场景。
4. 切换「大/中/小/列表」档位后再切分类（档位变化会正常作废缓存，应各重建一次，属预期）。
5. 缩放窗口后再切分类，列数应正确重排且不重建。
