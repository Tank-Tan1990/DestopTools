# 程序启动/运行后崩溃 —— 根因定位与修复

**日期**：2026-09-24
**反馈**：「程序运行后就崩溃，关闭了」
**结论**：**已定位到确切函数级位置并修复**。真凶与之前所有猜测都不同 —— 是一条**跨进程 COMCTL32 句柄失效**路径。

---

## 一句话结论

崩点是 `DesktopMirrorWindow::queryDesktopIconSize()` 里的这一句：

```cpp
HIMAGELIST hil = (HIMAGELIST)SendMessageW(lv, LVM_GETIMAGELIST, LVSIL_NORMAL, 0);
if (hil) {
    int cx = 0, cy = 0;
    if (ImageList_GetIconSize(hil, &cx, &cy) && cx > 0) { ... }
}
```

`LVM_GETIMAGELIST` 跨进程返回的 `HIMAGELIST` 是**dub 句柄**，它只在「原生桌面 ListView 仍存活且状态一致」时有效。而本程序启动后会把原生桌面 `hideNativeDesktop()`，桌面 ListView 也可能被 explorer 随时重建 —— **句柄一旦失效，COMCTL32 内部就直接踩到非法地址**。

- 异常被上层 SEH 消化掉时 → 程序继续跑（你就只看到"偶尔卡一下"）
- **时机不巧时 → 升级成进程级致命崩溃 → 程序自己关闭**

这解释了**两条历史反馈**：既解释了「运行 1 小时左右自己关闭」，也解释了今天的「运行后就崩溃」。

---

## 一、取证链：从"只有信号号"到"函数名 + 偏移"

### 1. 起点：崩溃日志给不出任何定位

```
===== 2026-09-24 20:52:19  SIGSEGV =====
异常代码: 0x0000000B          ← 这是**信号号 11**，不是真正的异常码
最后动作: layoutButtons:enter
```

**发现两个取证缺陷：**

| 缺陷 | 原因 | 后果 |
|---|---|---|
| 异常码是 `0x0B` 而非 `0xC0000005` | MSVC CRT 会把访问违例**转成 SIGSEGV 信号**并调用 `signal` handler —— 它**抢先**于 `SetUnhandledExceptionFilter` | 拿不到异常地址，也没有模块信息 |
| 崩点只到 `layoutButtons:enter` | 该版本在 `layoutButtons()` 内部**只有这一个埋点** | 范围太大，无从下手 |

### 2. 升维：VEH（向量化异常处理）

`AddVectoredExceptionHandler(1, ...)` 在**所有 SEH / CRT signal 之前**被调用，这是唯一能拿到真实异常的钩子。加上后立刻拿到：

```
===== 2026-09-24 21:19:49  VEH-故障异常 =====
线程: 0x1F0C
异常代码: 0xC0000005              ← 真正的 EXCEPTION_ACCESS_VIOLATION
异常地址: 0x00007FFE3D8C0B55  模块: COMCTL32.dll + 0x70B55
访存: 写入 @ 0x0000000057D50898   ← 一个 32 位量级的垃圾地址 = 句柄/指针截断的典型特征
最后动作: app-start
```

### 3. 决定性一击：调用栈 + `/MAP` 反查

x64 + MSVC 会为每个函数生成 `.pdata` unwind 信息，所以 `RtlCaptureStackBackTrace` **即使 release /O2 也能准确回溯整条链**。再配合 `.pro` 里新增的 `/MAP`（release 版无 `.pdb`，这是唯一符号来源），得到：

```
调用栈:
  #04 COMCTL32.dll + 0x70B55
  #05 COMCTL32.dll + 0x70BE7
  #06 COMCTL32.dll + 0x785C8
  #07 DestopTools.exe + 0x477AA   -> safeImageListGetIconSize() + 0xA
  #08 DestopTools.exe + 0x4324C   -> DesktopMirrorWindow::queryDesktopIconSize() + 0x70
  #09 DestopTools.exe + 0x4399C   -> DesktopMirrorWindow::readEntriesFromListView() + 0x14C
  #10 DestopTools.exe + 0x4544D   -> DesktopMirrorWindow::refresh() + 0x6D
```

**函数级定位完成。** 反查用的是本轮新增的可复用工具 `tools/addr2func.py`。

## 二、为什么表现成"崩在 layoutButtons"

`queryDesktopIconSize()` 的结果写进成员 `m_desktopIconSize`，而 `layoutButtons()` 会**消费**它。

于是失效瞬间有两种走向：

```
① 访存地址不可写 → 当场致命 AV   → 最后动作 = 当前 mark（可能在 layoutButtons 里）
② 访存地址可写   → 静默写坏内存  → 稍后在毫无关联的位置爆掉
```

`layoutButtons:enter` 之后立刻崩，正是 ② 的形态：**刷新阶段被写坏的数据，在紧接着的布局阶段被消费时爆掉** —— 所以崩溃现场看起来完全指向 layoutButtons，其实真凶在刷新阶段。

## 三、修复内容

### ✅ 1. SEH 包装（根治）

新增 `safeImageListGetIconSize()`，把裸调的 COMCTL32 调用关进 SEH：

```cpp
__declspec(noinline)
static bool safeImageListGetIconSize(HIMAGELIST himl, int* cx, int* cy) {
    __try {
        return ImageList_GetIconSize(himl, cx, cy) != FALSE;
    } __except (EXCEPTION_EXECUTE_HANDLER) {
        return false;
    }
}
```

异常时返回 `false`，调用方**照原逻辑**退到注册表兜底 —— **行为完全等价**（事实上该路径此前一直在走兜底）。

### ✅ 2. 熔断器（消除噪音）

```cpp
static bool s_lvIconSizeUsable = true;   // 一旦确证句柄不可用，本次进程内永久降级
```

拿到句柄却读不出尺寸 = 失效的**确证**（不是"ListView 还没就绪"，那种情况根本拿不到 `hil`）→ 断开熔断器。
效果：该路径不再每分钟白跑 8 次异常分发（异常分发不便宜，还会把崩溃日志刷满、掩盖真正的致命事件）。

**为什么零功能损失**：既然它一直失败，实际生效的一直是注册表兜底 —— 熔断前后行为完全相同。

### ✅ 3. 顺带修掉的两处真缺陷（**不是**本次崩溃根因）

| # | 位置 | 缺陷 |
|---|---|---|
| ① | `icongridwindow.cpp` `eventFilter` | 判据写成 `watched == qApp` 是**错的**（装在 qApp 上时 `watched` 是**事件接收者**，不是 qApp）→ 上一轮「点别处取消选中」**根本没生效**。已改为「只看鼠标按下的屏幕落点」，并把 `widgetAt` 结果**向上追溯**到 `DesktopIconButton`/`QLineEdit`（否则点图标上的文字会被误判成点空白） |
| ② | 同上 | 全局过滤器下 `watched` 可能是**非 QWidget**，而 `MouseMove` 分支里的 `static_cast<QWidget*>(watched)` 是不做检查的强转 → 潜在访问违例。已加"非 QWidget 直接放行" |

## 四、本轮沉淀的崩溃取证能力（长期资产）

| 资产 | 作用 |
|---|---|
| `.pro` 的 `QMAKE_LFLAGS += /MAP` | release 无 `.pdb`，这是唯一的**函数级符号来源**；`release/DestopTools.map` |
| `CrashTrace` 的 **VEH** | 抢在 CRT signal 前拿到**真实异常码 + 异常地址**（此前只有信号号 11） |
| `CrashTrace` 的**调用栈捕获** | `RtlCaptureStackBackTrace` + 逐帧"模块 + 偏移"，配合 `.map` 直接给出函数名 |
| **访存细节** | 记录"读/写 + 目标地址"，一眼分辨空指针 / 野指针 / 已释放堆块 |
| **线程 ID** | 区分"崩在 GUI 线程"与"崩在后台线程" |
| `CrashTrace::event()` | **直接落盘**的里程碑探针。修掉了一个真实设计缺陷：原来的 `mark()` 只写内存缓冲、**仅在崩溃时**才输出，所以 `normal-quit` 这类"正常收尾"标记**永远看不到** |
| `tools/addr2func.py` | 把地址反查成函数名 + 偏移；支持 `--stack-from-log` 直接解析最后一组调用栈 |

## 六、请你在真机上确认

1. **正常使用一段时间**（尤其切模式、整理桌面、改图标大小），观察是否还会自己关闭；
2. 若再次退出，看 `DestopTools\release\DestopTools_crash.log`：
   - 出现 **`normal-quit`**（新增的 `事件` 段） ⇒ 走的是**正常退出**流程
   - **没有** `normal-quit` ⇒ 进程是**被外部强杀**的（安全软件 / 任务管理器）
   - 出现 `SIGSEGV` ⇒ 还有真正的崩溃，此时日志里会**同时**有 `VEH-故障异常` 段，带**异常地址 + 调用栈**，直接丢给我即可一击定位
3. 顺带验证上一轮的两个功能修复：**点空白/收纳盒/Dock 能否取消选中**、**Ctrl 加选与 Shift 范围选是否正常**。
