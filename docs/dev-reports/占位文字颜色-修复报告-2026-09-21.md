# 搜索框占位文字「变黑」修复报告

日期：2026-09-21 22:30 ｜ 产物：`DestopTools/release/DestopTools.exe`（1255424 B @22:26:47）
范围：**只改输入框占位文字的颜色**，其它外观一律未动。

## 一、现象与实证

助手面板标题栏搜索框的「搜索」两字，**比它自己的底色更黑**，而不是灰。

把用户截图 PNG 直接解码（自解 zlib，本机无 PIL）后逐像素统计该区域：

| 项 | 值 |
|---|---|
| 搜索框底色 | `rgb(16,23,22)`（1054 px） |
| 「搜索」两字笔画 | `rgb(8,11,11)`（112 px） |
| 描边 | `rgb(16,58,53)`（53 px） |

笔画 **恰为底色的 ×0.5**，且无抗锯齿过渡 → 是「半透明黑叠在底色上」，不是灰色文字。

**回归定位**：把 `clipboard-images` 里全部历史 PNG 按比例取样分析 ——
09-19 / 09-20 的 13 张面板截图**占位字全是亮的**（亮于底=112），**只有 09-21 22:08 这一张是暗的**
⇒ 是当天引入的回归。

## 二、根因

> **占位文字的颜色根本不由样式表决定。**

- Qt5 的样式表**没有** `::placeholder` 选择器 → 项目里那几行 `QLineEdit::placeholder { color: ... }`
  **是死规则**（不报错、永不匹配）。实测：渲染值 = 白 50%，而不是规则里写的 45%。
- 真正生效的是 **`QPalette::PlaceholderText`**，它的默认值 = `Text` 角色取 **50% alpha**，
  即 `rgba(0,0,0,128)` —— **半透明黑**。
- 深色背景下，`0.5 × 黑` 合成出来就是「比背景更黑」的暗字（`rgb(8,11,11)` = `rgb(16,23,22)` × 0.5，与实测完全吻合）。
- 改主题色 / 拖透明度会触发全局重刷（`a.setStyleSheet(globalStyleSheet())` + 各窗口 onStyle + Qt repolish），
  这条链路上控件调色板会被重新推导，`PlaceholderText` 一落回默认值就变黑，并且**黑住不再自愈**
  —— 这就是用户说的「**改完主题色后就变成黑色**」。

---

## 三、修法（最小、且打不死）

`theme.h` 新增四个部位：

```cpp
inline QColor placeholderTextColor();            // 固定「禁用灰」= rgba(255,255,255,0.40)
inline void   applyPlaceholderColor(QLineEdit*); // 显式写 palette::PlaceholderText + 装守卫
class         PlaceholderColorGuard;             // 关键：重抛光后自动把颜色钉回去
inline void   applyLineEditStyle(QLineEdit*);    // 统一入口 = setStyleSheet + applyPlaceholderColor
```

- 颜色取 **`QMenu::item:disabled` 同款** `rgba(255,255,255,0.40)` —— 即项目里既有的「禁用灰」口径，
  与主题色、背景透明度**完全解耦**。
- 🚨 **只在创建时设一次挡不住主题热重刷**，所以 `PlaceholderColorGuard` 监听
  `StyleChange / PaletteChange / ApplicationPaletteChange / Polish`，之后立刻重设；
  幂等（值相同不写）+ `m_busy` 挡住 `setPalette` 引发的嵌套事件，不会来回抖动。
- `main.cpp` 另把**应用级 palette 的 `PlaceholderText`** 钉一次，覆盖那些只吃全局样式表、
  没有单独 `setStyleSheet` 的输入框（设置中心、反馈框、输入弹框等）。**只动这一个调色板角色。**
- 改走统一入口的调用点：`sidepanelwidget.cpp`×2、`filesearchwidget.cpp`×4（file/web 输入框）、
  `glassinputdialog.cpp`×1、`icongridwindow.cpp`×1。`QComboBox` 的 4 处保持原样（同病不同源，另行处理）。

## 四、验证（在**真实控件**上，不是替身）

新增 `tools/panelprobe`：`.pro` 用 `$$files(release/*.obj)` 把产品**已编译对象**全链进来（去掉 `main.obj`），
自己写 main → 构造**真实 `SidePanelWidget`** → `findChildren<QLineEdit*>()` 定位搜索框 → `panel->grab()` 量像素。
复跑：`python tools/run_panelprobe.py`

| 阶段 | 操作 | PlaceholderText（三组一致） | 实际渲染笔画 | 结论 |
|---|---|---|---|---|
| A | 启动后 | `rgb(255,255,255,a102)` | `rgb(112,116,115)` 亮于底 +94 | OK |
| B | 改主题色 #FF8A3D | 同上 | `rgb(116,113,112)` | OK（不跟随主题色） |
| C | 改回青色 | 同上 | `rgb(112,115,116)` | OK |
| D | 透明度拖到 0 | 同上 | `rgb(110,114,114)` | OK |
| **E** | **人为把 PlaceholderText 打成 `rgba(0,0,0,128)`（=「变黑」真身）** | 守卫**自动改回** a102 | 恢复 `rgb(110,114,114)` | **OK：变黑状态无法存活** |

阶段 E 是关键：它直接构造出用户看到的那个坏状态，而守卫在没有任何外部干预下把它救回来了。

用来判定 QSS 的 `color` 到底传播到哪个角色）。
