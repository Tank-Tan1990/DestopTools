## 0. 先说一件最重要的事：这一版为什么不会再「运行后就崩」

你上一轮报的「程序运行后就崩溃」，时间点落在 **20:48 那一版**（第三轮）之后。本轮把同样的两个问题重新做了一遍，但有一处**本质差别**：

20:48 那版给 `IconGridWindow` 挂了应用级过滤器 `qApp->installEventFilter(this)`，却**没有做类型检查**。而挂在 `qApp` 上的过滤器，收到的事件接收者**不止是 QWidget** —— 鼠标/绘制类事件会先派发给 **`QWindow`**（顶层窗口的平台侧对象，**不是** `QWidget` 的子类）。该函数后面的 `MouseMove` 分支里有：

```cpp
auto* w = static_cast<QWidget*>(watched);
const QPoint pos = (w == this) ? me->pos() : w->mapTo(this, me->pos());   // ← 对 QWindow 调用 QWidget 的成员
```

对一个 `QWindow*` 做 `static_cast<QWidget*>` 再调用其成员函数是**未定义行为**（必然崩）。这极可能就是那次崩溃的**新增**来源。

**本轮补上了闸门**，放在 `eventFilter` 最前面（在应用级分支之后、所有 `static_cast` 之前）：

```cpp
if (!qobject_cast<QWidget*>(watched)) return QWidget::eventFilter(watched, event);
```

除此之外，本轮**没有碰任何原生句柄、SEH、线程、崩溃溯源代码**（`desktopmirrorwindow.cpp` 一个字未改），改动全部落在 Qt 控件层逻辑上。

## 一、问题 1：分类来回切换 → 鼠标移动变慢（卡顿严重）

### 1.1 根因：顺序一变就整页重建，重建的代价是**重新排队取图标**

分类页缓存的命中判据是顺序敏感的：

```cpp
const bool stale = (page.viewMode != m_viewMode) || (page.signature != pageSignatureOf(currentItems()));
//                                                      ^^^^^^^^^^^^^ page.signature = sourcePath 序列，顺序敏感
```

于是**任何一次纯粹的顺序变化**（拖拽排序、`applyItemOrder` 的结果差异、Dock 侧同步顺序、盒内交换位置…）都会让这一页被判 `stale`，走进：

```
deleteLater 整页按钮 → 重新 new 每个 DesktopIconButton → 每个按钮重新入队取图
                                                          （s_iconTimer：30ms / 每拍 1 个）
```

一个几十~上百项的「图标很多」的分类，重建后就是**几秒的连续界面占用**：GUI 线程每 30ms 被唤醒一次去走 Shell 取图（单次几 ms ~ 数十 ms，机械盘 + 安全软件抢盘时更慢）。表现就是**鼠标移动发涩、拖动一顿一顿**，而且「来回切换」会让它反复发生。

**而顺序变化根本不需要重建按钮**：按钮对象、图标位图、信号连接全都还能用，只要按新顺序把它们放回布局。

### 1.2 修复

| # | 改动 | 位置 | 性质 |
|---|---|---|---|
| P1 | **HIT-RESORT**：集合相同、仅顺序不同 ⇒ 按新顺序把**同一批按钮**放回布局（零销毁、零取图） | `adoptCachedGridPage()` | 质变（消灭主要矛盾） |
| P2 | **落盘防抖**：值未变不写；首次同步写；之后 400ms 合并；析构兜底 `flushCurrentCategory()` | `saveCurrentCategory()` + 新增 `flushCurrentCategory()` | 零功能变更 |
| P3 | **换页期间合批重绘**：`park + prepare + adopt/apply` 全程 `setUpdatesEnabled(false)`，末尾无条件恢复 | `switchCategoryPage()` | 零功能变更 |
| P4 | **几何重排列数早退**（拖动窗口边缘是逐像素 resize） | `relayoutGridForGeometry()` | 零功能变更 |

**P1 的安全兜底（任何一步对不上就退回原来的全量重建，原行为永远是兜底）**：

- 视图档位不同 → 重建；
- 把两侧签名**各自排序后**比对（= 多重集相等，重复项也计）不通过 → 重建；
- `gridItemKey`（归一化 + 小写）有对不上 / 有重复 / 数量不符 → 清空 `resortOrder` → 重建。

> 🚨 这里是**纯计算、落地之前**判定的：判定失败时按钮**尚未被动过**，直接交给原分支 `deleteLater`，不会出现「改了一半」的中间态。

**P2 为什么必须防抖**：`saveCurrentCategory()` 的调用点就是 `activateCategoryTab()` / `setCurrentCategory()` —— **每一次**分类切换。它内部是 `saveValue` + **`sync()`（同步刷 INI）**，机械盘 + 360 抢盘下单次可达数十~数百 ms，且全在 GUI 线程。它要存的只是「下次打开默认选中哪个分类」。
**首次写入仍走同步**：那是启动路径（用户还没开始来回切），且必须保证 `IconGridWindow/currentCategory` 键始终存在；**析构由 `flushCurrentCategory()` 兜底**，否则「切完 400ms 内关窗」这次切换就永远没落盘。

**P3 的恢复是安全的**：`switchCategoryPage()` 函数体内**没有中途 return**，所以 `setUpdatesEnabled(false)` 与恢复首尾成对，不存在「漏恢复 = 网格永远不刷新」的路径。

## 二、问题 2：拖拽多个图标后进入多选态，点收纳盒取消不掉

### 2.1 根因：三种最自然的「取消选中」手势，走的都不是本窗口的事件路由

选中集合 `m_selection` 是本窗口的私有状态，而：

1. **点网格空白** —— 可视区被 `QScrollArea` → `viewport` → `m_gridContainer` 层层覆盖，点击落在 `viewport` 上就被 hover / 拖放语义消费掉，**永远到不了** `mousePressEvent` 里那句 `clearSelection()`；
2. **全屏收纳模式** —— `mousePressEvent` 开头就 `QWidget::mousePressEvent(event); return;`；
3. **点收纳盒 / Dock / 设置中心** —— 事件完全在**另一棵 QWidget 树**上，本窗口无从得知。

于是唯一还能取消的入口只剩「点击另一个图标」，所以只能**挨个点掉** —— 与你的描述完全一致。

### 2.2 修复：应用级事件过滤器（挂在 `qApp`，析构摘除）

在 `eventFilter` 最前面新增分支，**只在「本窗口确实有选中项」时才做落点查询**（无选中项时只比一个 bool，直接落到常规逻辑）：

```cpp
if (event->type() == QEvent::MouseButtonPress && (!m_selection.isEmpty() || m_anchor)) {
    if (左键或右键 && !isEditingAnyIcon() && !m_menuOpen) {
        QWidget* hit = QApplication::widgetAt(me->globalPos());
        bool onIcon = false;
        for (QWidget* w = hit; w; w = w->parentWidget())      // 向上追溯：命中的可能是图标内的子对象
            if (qobject_cast<DesktopIconButton*>(w)) { onIcon = true; break; }
        if (!onIcon && !qobject_cast<QLineEdit*>(hit) && !qobject_cast<QMenu*>(hit))
            clearSelection();
    }
}
```

**为什么挂 `qApp` 而不是本窗口**：上面三条根因里 ② ③ 走的都不是本窗口的事件路由；挂 `qApp` 后能看到**本进程内所有窗口**（Dock / 各收纳盒 / 设置中心 / 对话框）的鼠标按下。

**必须放行的四类（否则会改坏既有功能）**：

| 放行对象 | 原因 |
|---|---|
| `DesktopIconButton` | 按钮自己要处理 Ctrl 加选 / Shift 范围选；先清会让加选失效 |
| `QLineEdit` | 改名输入框；编辑途中不能抹掉选中 |
| `QMenu` 落点 | 分类标签/其它菜单项的点击不该抹掉图标选中 |
| `m_menuOpen` 期间 | 本窗口右键菜单是**原生模态循环**；此处清空会让 `onIconDeleteRequested()` 的「该项在选中集合里就删整组」落空 —— **多选后右键删除会退化成只删一个** |

**已知边界**：点击**其它进程**窗口（浏览器 / Explorer）不触发（事件不进本进程）—— 与 Windows 桌面「点别的程序时桌面选中仍保留」的行为一致，非缺陷。
