# 收纳盒交换图标位置后「十几秒才慢慢出现」—— 修复报告

日期：2026-09-24　｜　触发：上一轮「鼠标卡死 6 条修复方向」引入的回归
用户描述：**「收纳盒中的图标交换一下位置，然后半天不刷新」** → 追问后明确：
- 界面：**区分分类的那个界面**（网格视图，用 `DesktopIconButton`）
- 表现：**位置一直不出现，要等很久（十几秒以上）才慢慢出来**
- **重启也照样** ⇒ 稳态问题，不是首刷冷缓存

---

## 一、根因（一句话）

`DesktopIconButton::processIconQueue()` 用**固定 `batch = 1` + 30ms 定时器间隔**取图，
所以一次重建的整页图标必须 `30ms × N` 逐个"冒"出来（本机 N≈200 ⇒ 6 秒起）；
而**我在上一轮加的"上一拍超预算则让出"又把它翻了一倍** ⇒ 十几秒 —— 正是用户看到的现象。

**关键错配**：稳定态下 `DesktopScanner::loadIcon()` 是**先查进程内图标缓存**的，
单次 ≈ **0ms**。缓存命中根本不该被"每 30ms 放行一个"限速。
上一轮我给 **Dock 侧**（`setDockButtonIcon` / `processDockIconQueue`）做了"缓存命中→同步出图 + 按时间预算循环"，
**却漏了网格/收纳盒用的 `DesktopIconButton`**，还顺手把它的让拍加上，于是"没修好反而更慢"。

这正好对上用户的提示：**「走缓存，没有变化就不需要刷新」** —— 缓存命中就该是瞬间的。

---

## 二、修复

### 1）主修：`DesktopIconButton::processIconQueue()` 改为**按时间预算循环**（与 Dock 侧同构）

```cpp
// 原：固定 batch = 1 + 30ms 间隔 ⇒ 30ms × N 逐个出现
// 新：循环取到时间预算（kIconProcessBudgetMs = 20ms）为止
QElapsedTimer burst; burst.start();
while (!s_iconQueue.isEmpty()) {
    QPointer<DesktopIconButton> btn = s_iconQueue.takeLast();
    if (!btn) continue;
    btn->m_iconQueued = false;
    btn->loadIconNow();
    if (burst.elapsed() >= kIconProcessBudgetMs) break;   // 到预算收手，剩余留给下一拍
}
s_lastBurstMs = burst.elapsed();
```

效果：

| 场景 | 改前 | 改后 |
|---|---|---|
| 交换位置 / 重建整页（缓存命中，稳态） | `30ms × N`（≈6s；叠加让拍≈12s+） | **同一拍内铺满**（≈0ms，视觉瞬间） |
| 首次加载（真冷项，Shell 长尾数百 ms） | 每拍 1 个 | 每拍 1~2 个（吃满预算就收手）—— **单拍阻塞上限不变** |

**为什么这是"不破坏"的**：单拍阻塞上限仍由预算 20ms + "上一拍超预算则让出"双重约束，
UI 依然有确定的空档；改变的只是"缓存命中的项不再被定时器间隔白白限速"。

### 2）附修：廉价戳漏了 `categories.ini`（我上一轮新增代码的真缺口）

`cheapDesktopStamp()` 原来只统计**桌面目录**（路径 + mtime + 直接子项名），
但 Dock / 收纳盒的呈现内容 = **桌面目录 × 分类映射**。
用户**交换顺序 / 改分类**时，桌面目录的 mtime 与子项名**都不变** ⇒ 被误判成"没有变化"直接跳过刷新。

新增 `CategoryStore::storeFilePath()`（`categorystore.h/.cpp`，唯一实现里取路径，避免 org/app 字符串在别处重复而漂移），
把 `categories.ini` 的 **mtime + 大小**纳入廉价戳。

> 说明：真正由桌面变化触发的刷新走 `WM_DESKTOP_NOTIFY`（已置 `m_forceRescan`，本来就绕过本门），
> 本次是把"绕过之外的判据"补齐 —— 让"没有变化"这个判断与"呈现内容"对齐。

## 三、已验证排除的项（都带证据，避免下次重复挖）

| 怀疑 | 结论 | 证据 |
|---|---|---|
| `ForegroundGate` 误判全屏导致队列永久早退 | **排除** | 用 ctypes 在同机复现全部判据：`SHQueryUserNotificationState = 5 (ACCEPTS_NOTIFICATIONS)`、前台窗口 `Chrome_WidgetWin_1` 矩形 (691,3)-(1918,1043) 不覆盖 `rcMonitor` ⇒ **`fullscreenActive() = False`**（工具：`tools/probe_fullscreen_gate.py`） |
| `mainwindow.cpp` / `fencebox.cpp` 被改坏 | **排除** | 本轮 mtime 未变（仍为 12:49 / 12:50），`refreshDesktop()`、盒内落点判定不是本轮改动 |
| `sameGridItemSet` 早退吞掉交换 | **排除** | 它逐项按下标比对 `sourcePath`，**顺序敏感**，交换必被识别为"变了" |
| `layoutButtons()` 清空 `m_iconQueue` 丢掉任务 | **排除** | 清空在 `:1769`，按钮创建在 `:1991/:2146` 之后 ⇒ 顺序"先清后建"，安全 |
| 图标缓存键不一致导致恒不命中 | **排除** | `g_iconCache` 全项目仅在 `desktopscanner.cpp` 出现，读/写都走同一个 `iconCacheKey()` |
