## 一、现状（为什么勾了没反应）

键 `Appearance/menuLabelShow`（0=始终显示 默认 / 1=悬停显示）**又是一处"空设置"**：
全项目只有 `settingcenterdialog.cpp` 在读写在自娱自乐，产品里**没有任何消费者**。
所以「悬停显示」勾了毫无反应；「始终显示」看着正常，只是因为历史实现本来就是常驻。

（这与上一轮「分区标签切换」`Appearance/tagSwitchMode` 是同一类问题，本轮沿用同一套基础设施：

## 二、改动

### 1. 收纳盒窗口（`IconGridWindow`，含主整理窗口）—— 左边红框
- 新增 `loadMenuRevealMode()` / `reloadMenuRevealMode()` / `applyMenuRevealVisibility()`。
- `applyMenuRevealVisibility()` 是这 5 个头部按钮（**锁 / 视图 / 添加 / 菜单 / 展开**）的**唯一显隐出口**：
  `show = (模式 == 始终显示) || 鼠标在本窗口内`。
- 新增 `enterEvent()`；`leaveEvent()` 里补同样的判定（原有光标复位逻辑不动）。
- 全屏接管（分区平铺）模式下整条 `headerBar` 本来就隐藏 → 该函数直接早返回；
  退出全屏后由 `setFencesMode(false)` 末尾补调一次，避免"无条件 show()"把本该隐藏的按钮亮出来。
- `showEvent()` 重读设置并按**光标真实位置**（`QCursor::pos()` 映射到窗口坐标）定初始显隐 ——
  不能只看成员变量：窗口隐藏期间 Enter/Leave 不再派发，成员会停在过期值。

### 2. 桌面助手面板（`SidePanelWidget`）—— 右侧红框
- 同样三个函数 + `enterEvent()/leaveEvent()`（面板铺满整个 `AssistantWindow`，边距为 0，
  故"移入面板"与"移入桌面助手界面"是同一件事）。
- 4 个按钮（**搜索 / 组件市场 / 菜单 / 展开**）装进一个**定宽容器** `m_menuBtnBox`：
  悬停模式下只隐藏容器里的按钮，容器照旧占住原宽度 →
  **左侧搜索框宽度恒定**，不会随鼠标一进一出反复伸缩。

### 3. 设置中心（`settingcenterdialog.cpp`）
- 写盘 `Appearance/menuLabelShow` 之后加一行 `ThemeManager::notifySettingChanged(...)`：
  已打开的所有收纳盒/主窗口 + 助手面板**立即就地切换**，不必重开窗口或重启。

## 三、设计要点（为什么用 Enter/Leave 而不是逐像素追踪）

QApplication 派发 Enter/Leave 时只在与"新旧落点"有关的层级上发事件 ——
鼠标从窗口背景移到自己子部件上时，**父部件不会收到 Leave**，因此
在标题栏按钮之间、或从标题栏划到时钟区，都不会闪隐；只有真正离开整个窗口才收起。
窗口本身 `setMouseTracking(true)`（原有），无框 `WS_EX_NOACTIVATE` 不影响该机制。
