# 菜单弹层背景未被透明度控制 —— 根因与修复报告（2026-09-21）

> 用户反馈：收纳盒右键菜单 / 桌面助手菜单 / 新建分类菜单 / 待办菜单及三个子菜单（提醒·字体·优先级），
> 红框内的**背景没有被透明度控制**；设置中心「整理规则」的**表头**也有同样观感。
> 结论先行：**QMenu 拿不到 alpha 合成位**，它的半透明背景一直合在**黑色**底上 —— alpha 其实一直在变，
> 但画面上透不出桌面。已用「触发平台窗口重建」根治，并以**真实像素**验证通过。

---

## 1. 上一轮为什么没发现

上一轮的验收是**字符串级**的：断言 `menuStyle()` 里背景 alpha 随滑块变化（27 项断言 PASS）。
但**字符串对 ≠ 画面对**。本次改为「把弹层弹在纯白画布上，两档透明度截屏读真实像素」，
一次性暴露了真相。

## 2. 根因（实测证据）

### 2.1 像素探测：背景 alpha 在**黑底**上合成

判据：白底画布上 alpha 变小**应当变亮**（与白混合）。实测（`tools/popupprobe`）：

| 对象 | `WS_EX_LAYERED` | t=100（alpha 1.00） | t=0（alpha 0.15） | 判读 |
|---|---|---|---|---|
| ① QMenu 现状 | **N** | rgb(16,22,23) | rgb(4,6,6) | **变暗** → 黑底合成 |
| ② QMenu +Translucent | **N** | rgb(16,22,23) | rgb(2,3,3) | 变暗 → 黑底 |
| ③ 子菜单 现状 | **N** | rgb(16,22,23) | rgb(10,47,53)\* | 变暗 → 黑底 |
| ⑥ 对照 QWidget(`Window\|Frameless`) | **Y** | — | — | 能拿到合成位 |
| ⑦ 对照 QWidget(`Qt::Popup`) | **Y** | — | — | 能拿到合成位 |

\* 采样点落在 item 高亮上被青色污染。按「底色×alpha 叠 `item:selected` 青 0.20」手算得 (9,45,50)，
与实测 (10,47,53) 吻合 —— 反证**底层是黑**（若为白底应为 ≈(220,221,224)）。

**反推底层颜色**：`0.15×(17,22,24) + 0.85×U = (4,6,6)` → `U ≈ (2,3,3)` ≈ **纯黑**。
机制：Qt 对顶层窗口的 raster backing store 先清成透明 `(0,0,0,0)`；**非 layered 窗口**用 GDI BitBlt
提交时**忽略 alpha**、只取 RGB = 0 → 屏幕上是黑的。

### 2.2 属性级排查：只有「重建平台窗口」能拿到合成位

（`tools/wndprobe`，不弹窗、3 秒出结果）

```
对照 QWidget(Window|Frameless)        priorHandle=N attr=Y fmtAlpha=Y AB=8 LAYERED=Y
对照 QWidget(Qt::Popup)               priorHandle=N attr=Y fmtAlpha=Y AB=8 LAYERED=Y
A QMenu 基线                          attr=N fmtAlpha=N AB=-1 LAYERED=N
B QMenu +Translucent                  priorHandle=Y attr=Y fmtAlpha=Y AB=8 LAYERED=N   ← 窗口已建，属性设晚了
C QMenu +Translucent +NoDropShadow    同 B → LAYERED=N
D QMenu 显式 flags 重建 +Translucent   attr=Y fmtAlpha=Y AB=8 LAYERED=Y   ← 唯一成功
E QMenu(无 parent) +Translucent        LAYERED=N
F QMenu 先建窗→设属性→hide/show         fmtAlpha=N AB=0 LAYERED=N
```

**机制**：Qt 只在**建窗那一刻**按 `WA_TranslucentBackground` 决定 `QWindow::format()` 的 alpha buffer，
Windows 平台插件再据 `format().hasAlpha()` 加 `WS_EX_LAYERED`。QMenu 在构造 / 首次 `winId()` 时
就把平台窗口建好了 → 必须 `setWindowFlags` **触发平台窗口重建**，让新窗口带着属性创建。
`setWindowFlags(windowFlags())` 无效：**Qt 判等直接 `return`**（QMenu 默认 flags 实测 `0x8800f009`
= Window|Popup|TitleHint|SystemMenuHint|Min|Max|CloseButton|FullscreenButton，**不含 FramelessWindowHint**）。

## 3. 修复

### 3.1 统一入口（`theme.h`）

```cpp
inline void applyMenuStyle(QMenu* menu) {
    if (!menu) return;
    // 保留调用方已有 flags（如 WindowStaysOnTopHint），只"确保"含这三项 → 触发平台窗口重建
    menu->setWindowFlags(menu->windowFlags()
                         | Qt::Popup | Qt::FramelessWindowHint | Qt::NoDropShadowWindowHint);
    menu->setAttribute(Qt::WA_TranslucentBackground, true);
    menu->setStyleSheet(menuStyle());
}
```

**调用时机必须在首次 `popup()`/`exec()` 之前**。用 `|=` 是为了无论调用方在前后怎么调
`setWindowFlag()` 都不会丢 `WindowStaysOnTopHint`、也不会跳过重建。

### 3.2 8 处调用点全部替换（残留 0，脚本核过）

| 文件 | 处 | 内容 |
|---|---|---|
| `todostore.cpp` | 4 | 待办条目主菜单 + 提醒管理 / 字体设置 / 优先级三个子菜单 |
| `icongridwindow.cpp` | 2 | `createAddMenu()` + 分类标签右键菜单 |
| `mainwindow.cpp` | 1 | 桌面图标右键主菜单（图1 那张） |
| `sidepanelwidget.cpp` | 1 | 桌面助手菜单（图2 那张） |

`icongridwindow.cpp` 那一处把 `setWindowFlag(WindowStaysOnTopHint, true)` 挪到 `applyMenuStyle()` **之前**
（配合 `|=`，两者任意顺序都安全，挪动只为可读性）。

**改动同时覆盖**：圆角外区域从原来的"黑角"变成真正透明；`QMenu` 原有的系统投影消失
（与产品其它无边框窗一致 —— 各对话框同样用 `FramelessWindowHint | NoDropShadowWindowHint`）。

## 5. 本次**未做**、需要你拍板的两项

### 5.1 表头（图4 那张）

实测结论：**表头的 alpha 是生效的**（`⑤ 表头` t=0→rgb(219,220,220)，`OK`；与表体同档 175/176 同向变亮）。
产品里它看着比数据行"实"，是**叠加层数**问题：

- 表头 = 窗口背景 + 内容面板 + 表格背景 + `QHeaderView::section` → **4 层**半透明深色叠加
- 数据行 = 窗口背景 + 内容面板 + 表格背景（`item{background:transparent}`）→ **3 层**

每多叠一层就更实一点，这是物理必然，不是"没跟随"。
**若你仍希望表头更透**，可选改法：把 `QHeaderView::section` 的 `background-color` 改成 `transparent`，
只留底部 1px 描边 —— 表头会与数据行同色，**失去色带区分**。要不要改，你说一声。

### 5.2 QComboBox 下拉弹层

实测：`combo->view()->window()`（下拉弹层载体）的 `WS_EX_LAYERED` **同样是 0**（修复前），
但**上面这套手法修不了它** —— 施加同样的 `setWindowFlags + Translucent` 后 **LAYERED 仍为 0**
（它的 container 会自己重置 flags）。也就是说下拉框弹层大概率也是"黑底合成"。

需要单独立项（可行方向：子类化 `QComboBox` 重写 `showPopup()`，或在 container 首次显示前用
Win32 直接干预）。你这次没圈它，我**没有动**，避免引入未验证的风险。

# 第二轮（2026-09-21 21:56）：长期持有菜单的「样式烘死」

## 1. 用户反馈
「这个菜单没有控制上，也要被透明度控制，不要一下写死了」—— 截图 = 桌面整理窗标题栏 **「+」按钮** 弹出的
**「新建分类 / 新建收纳盒」** 菜单。第一轮修好 LAYERED 之后，其它菜单都跟随了，**只有它不变**。

## 2. 根因（与第一轮完全独立的第二个原因）
全项目 `QMenu` 创建点共 8 处，其中 **7 处是"每次弹出时新建的局部对象"**
（`QMenu menu(this); …; menu.exec(pos);`）→ 每次弹出都重跑 `menuStyle()`，天然拿最新 alpha。

**唯一例外**：`icongridwindow.cpp:904`

```cpp
addBtn->setMenu(createAddMenu());   // 一次创建，长期挂在 QToolButton 上（InstantPopup）
```

`createAddMenu()` 里 `new QMenu(this)` + `Theme::applyMenuStyle(menu)` 只执行**一次**，之后这个菜单对象被
一直持有。而 `applyMenuStyle()` 里的 `setStyleSheet(menuStyle())` 只在**创建那一刻**跑过一次 ——
此后改主题色 / 拖透明度都不会再更新它。

`grep setMenu(` 全项目**仅此一处**，与用户截图完全对应。这也解释了为什么"看起来只有这一个菜单没被控制"。

## 3. 实测证据（`tools/menualpha` 新增 case ⑩/⑪，用产品真实 `theme.h`）

| case | 做法 | LAYERED | t=100 | t=0 | 判读 |
|---|---|---|---|---|---|
| ⑩ | 每次弹出前重刷 `setStyleSheet` | Y | rgb(16,22,23) | rgb(219,220,220) | 跟随 ✓ |
| ⑪ | 只在创建时设一次（= 产品现状） | Y | rgb(16,22,23) | **rgb(16,22,23)** | **停在旧值 ✗** |

⑪ 两档采样值**一模一样**，而 `LAYERED=Y`（渲染层完全正常）⇒ 不是渲染问题，是**样式字符串停留在创建那一刻**。

## 4. 修复（`theme.h::applyMenuStyle`，一处改动覆盖所有菜单）

```cpp
if (!menu->property("dt_menuStyleHooked").toBool()) {
    menu->setProperty("dt_menuStyleHooked", true);
    QObject::connect(menu, &QMenu::aboutToShow, menu,
                     [menu]() { menu->setStyleSheet(menuStyle()); });
}
```

- `aboutToShow` 在平台窗口**显示之前**发出 → 此刻 `setStyleSheet` 不会隐藏/重建窗口（安全）。
- 对 7 处"新建即弹出"的菜单无副作用（重刷一次而已）；对长期持有的菜单是**必需**。
- 🚨 `Qt::UniqueConnection` 对 **lambda 无效**（Qt 无法比较仿函数）→ 用动态属性做幂等标记。

## 5. 验证

- 修复后 case ⑪ → `t=0→rgb(219,220,220)` [跟随 ✓]。
- 构建走 `--full`（改的是被所有 TU 包含的 `theme.h`，避免 inline 定义 ODR 不一致）：`NMAKE_EXIT=0`，
  exe 1251840 → **1252352 B @21:56:03**。
- 产物断言：`dt_menuStyleHooked`（ASCII）hit=1 → 新码已进产物；上轮 `QMenu::item:selected` /
  `QMenu::separator` / `QToolButton::menu-indicator`（UTF-16）各 hit=2 → 无回归。
- ⚠️ `setProperty("...")` 的参数是 `const char*`，在 exe 里是**窄字符串**，断言必须按 ASCII 搜（按 UTF-16 搜会得到 0 命中）。

## 6. 请复测

桌面整理窗标题栏 **「+」按钮** → 菜单弹出时背景应**跟随透明度**；拖动透明度滑块后**再打开该菜单**，
背景应立即变化（无需重启）。其余菜单（右键菜单 / 子菜单 / 抽屉菜单）行为不变。

## 7. 回退点

`theme.h::applyMenuStyle()` 里删掉上面那段 `aboutToShow` 连接即可（其余不动）。
