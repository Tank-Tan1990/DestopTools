> dock内的图标，拖拽到收纳盒分类里面，能否直接出现拖动光标,图标直接插入到光标位置（收纳盒内拖动图标，出现的位置光标）

## 一、先取证：原来的行为是什么

| 环节 | 原状 |
|---|---|
| Dock 图标拖拽 | **不是 Qt 拖放**。`DockIconButton::mouseMoveEvent` 直接 `move()` 把按钮本体跟手移动（自定义实现），全程没有 `QDrag` / MIME。 |
| 收纳盒（FenceBox / 网格）接收 | 只处理 Qt 拖放事件（`dragEnter/dragMove/drop`）。**Dock 的拖动到不了这里** —— 鼠标事件被 Dock 窗口自己持有。 |
| 收纳盒**内部**拖拽 | 早就有一条“将插入到此处”的竖直指示线：`IconGridWindow::updateGridInsertMarker`（网格）/ `FenceBox::updateInsertMarker`（盒内）。 |
| Dock → 收纳盒 落点 | 已有链路：`DesktopMirrorWindow::onIconDragMove` 每 40ms 发 `iconDragHoverChanged(QCursor::pos())` → `MainWindow::onDockIconDragHover` → `resolveBoxAt()` 命中的盒子**亮一圈边框**；松手时 `m_boxDropResolver` 调 `scheduleDockItemsIntoBox()`。 |
| 落点位置 | 🚨`m_allItems[category].append(item)` —— **一律堆到分类末尾**，与光标位置无关。 |
| 光标反馈 | 无（DragMoveCursor 只在 `DesktopIconButton` 的 `QDrag` 路径上设过）。 |

⇒ 两条缺口：① 拖动悬停时没有“会插到哪个位置”的指示；② 插入位置永远是末尾。

## 二、改动

### 1. `FenceBox`（全屏收纳模式下的分类盒子）
新增 public 三件套（内部复用已有的 `targetIndexFromPos` / `updateInsertMarker` / `hideInsertMarker`）：

```cpp
bool showExternalDropMarker(const QPoint& globalPos, int* outIndex);  // 命中盒内网格 → 显示竖线 + 回传下标
int  externalDropIndexAt(const QPoint& globalPos) const;              // 只查询下标（松手时用），-1 = 不在盒内
void hideExternalDropMarker();
```
为什么必须单独做一套：外部拖拽的鼠标事件被**发起方窗口**（Dock）持有，本盒收不到 `QDragMoveEvent`，只能由窗口按全局坐标把“光标在哪”转发进来。

### 2. `IconGridWindow`（收纳盒窗口 / 主整理窗口）
```cpp
bool updateExternalDropIndicatorAt(const QPoint& globalPos, int* outIndex);  // 悬停：显示竖线 + 回传下标
int  externalDropIndexAt(const QPoint& globalPos) const;                     // 只查询下标
void clearExternalDropIndicator();                                           // 收起
void setCategoryOrderedItems(const QString& category, const QVector<DesktopItem>& items);  // 顺序落盘（见坑 1）
```
命中口径与既有的 `dropCategoryAtGlobal` 对齐：
- ① 全屏盒子视图 → 转发给命中的 `FenceBox`（用的是**与盒内拖拽完全相同的那条线**）；
- ② 窗口化网格视图 → 用本窗口的 `m_gridInsertMarker`；判定以**滚动区 viewport** 为准（内容宽可大于视口，用容器矩形会误判到视口外），且 `m_gridScroll` 与 `m_gridContainer` 都须可见（全屏模式下这两者是隐藏的）。
- 指示线只在图标网格上出现；拖到标题栏 / 分类标签栏时光标仍给“可放置”，但落点按“追加末尾”（`outIndex = -1`）。

### 3. `DesktopMirrorWindow`（Dock）
```cpp
void setDragOverBox(bool on);   // 悬停在收纳盒上 → Qt::DragMoveCursor；否则 unsetCursor
```
- 新增成员 `m_dragOverBox`、`m_dragHoverNotified`；
- `abortActiveDrag()` / `finishDrag` 都复位；
- 🚨`abortActiveDrag()` 补发 `iconDragFinished()`（条件 `wasActive && m_dragHoverNotified`）——见坑 2。

### 4. `MainWindow`
- `onDockIconDragHover`：命中窗口显示指示线，**其余窗口一律 `clearExternalDropIndicator()`**（光标 40ms 才来一次，有一个没清就会残留）；同时 `m_dock->setDragOverBox(hit != nullptr)`。
- `onDockIconDragFinished`：全部窗口清指示线 + Dock 光标复位。
- `m_boxDropResolver`：松手时 `t.window->externalDropIndexAt(pos)` 取插入下标，传给 `scheduleDockItemsIntoBox(..., insertIndex)`。
- `scheduleDockItemsIntoBox(..., int insertIndex = -1)`：
  - 插入改为 `dst->insert(insertAt, item)`，多选整组时逐项 `++insertAt`（整组连着插在光标那一格，保持相对顺序）；
  - 目标分类里若已有同路径先摘掉，且**摘掉位置在插入点之前时插入点同步前移**；
  - 原 ① 的“摘掉其它分类同路径条目”**跳过目标分类**（目标分类的摘除会改变插入下标，必须与插入一起算）。

## 三、三个坑（都已在代码里留注释）

**坑 1（最关键）：顺序键必须先落盘，否则插了等于没插。**
主整理窗口的 `setItems()` → `applyItemOrder()` 会按**磁盘 INI 里的顺序**重排图标；新收进来的文件路径不在旧顺序里 → 被当作“未放置项”**追加到末尾**。所以插入后、`setItems()` **之前**必须先把新顺序写盘（`setCategoryOrderedItems()` → 内部 `saveItemOrder()`）。
收纳盒窗口（`m_isBoxWindow`）没有顺序键，其显示顺序就是传入顺序，无需处理。

**坑 2：拖动被中止时不会有 `iconDragFinished`，指示线会留在屏幕上。**
`onIconDragEnd` → `finishDrag` 会发 `iconDragFinished`；但 `onIconReleased` → `abortActiveDrag()` **不发**。拖动被系统提前中止（源按钮被重建 / z 序变化）走的正是后者 ⇒ 松手后竖线不消失。已在 `abortActiveDrag()` 补发，并加 `m_dragHoverNotified` 闸门 —— 否则每次**单击** Dock 图标（press 时 `m_dragActive` 无条件置 true）都会触发一轮“遍历所有收纳盒窗口清指示线”的无谓开销。

**坑 3：光标形状由最上层窗口决定，两边都要设。**
Dock 是全屏镜像窗、收纳盒是 band 窗，两者叠放关系随模式变化。所以 `DesktopMirrorWindow`（Dock 侧）与 `IconGridWindow`（收纳盒侧）**都**设 `Qt::DragMoveCursor`，任一层在最上面都能看到反馈。

## 五、请重点实测

1. Dock 图标拖到**收纳盒窗口**（窗口化分类页）上：出现竖直指示线并跟随光标，松手后图标**出现在光标那一格**，而不是堆到末尾。
2. 拖到**全屏收纳模式的某个盒子里**：同款竖线（盒内与盒外拖拽看到的应是同一条线）。
3. 拖动过程中光标应变成“移动/可放置”形状；**拖到壁纸（壁纸/盒间空白）上应恢复原光标**，松手不生效。

5. 多选（Ctrl/画框）整组拖入：整组应连着插在光标位置，顺序不乱。
6. 拖动中途按 Esc / 拖动被中止：竖线与光标都必须复位，不留残影。
