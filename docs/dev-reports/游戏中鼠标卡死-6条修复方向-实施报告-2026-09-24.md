## 二、逐条实施细节

### 方向①（**刻意改道**，必读）

报告原话是「把桌面扫描/图标提取挪到**工作线程**（QtConcurrent/QThread），GUI 线程只收结果」。实施时判定**不可行**，依据两条硬事实：

1. **`DesktopScanner::loadIcon` 的既有约束**：源码注释明确写着「**仅应在主线程调用（STA 安全），不要在后台线程取图标以免触发 Shell 死锁**」。Shell 的 `IShellExtInit` / `IExtractIcon` 是 STA COM 组件，放进工作线程会引发 Shell 死锁甚至崩溃 —— 这正是本项目 `DesktopIconButton` 曾经踩过的历史坑（当时才不得不给它做 30ms 队列 + 分帧）。
2. **`DesktopScanner::scan()` 并非热点**：`NativeListView` 模式下 App 根本不调用它；真正耗时的是**逐项 `SHGetFileInfoW` 取图**（实测 5.15 ms/项，长尾单项 485 ms）。

**改道后的实现**（等价效果，且零线程风险）：

- `DesktopScanner` 新增两个小接口（`desktopscanner.h:52` / `:55`）：
  - `iconCacheKey(item, sizeHint, arrowScale)` —— 把缓存键算法**抽成唯一实现**，`cachedIcon()` 与 `loadIcon()` 共用（`desktopscanner.cpp:398` / `:435`），唯一目的是防止两处各写一套而漂移。
  - `cachedIcon(...)` —— **只查缓存、零 Shell 调用**。回收站（`645ff040…`）恒返回空（它要实时反映满/空），强制走实时路径。
- Dock 布局时（`desktopmirrorwindow.cpp:1837 setDockButtonIcon`，被 `:2036`/`:2191` 两个 createButton 调用）：
  - **缓存命中 → 立刻同步设图**（与旧实现逐字节一致，稳态零行为变化）；
  - **未命中（首刷 / 桌面刚新增的项）→ 只入队**，由 `m_iconQueueTimer`（30ms）异步取。
- 新增 `processDockIconQueue()`（`desktopmirrorwindow.cpp:952-989`）：每拍取到 **12 ms 预算**为止；若上一拍已超预算，本拍**直接让出**（避免长尾连成一片）；队列 > 8 时用 `ConditionalHooksGuard` 摘键盘钩子。

> 取舍一句话：**把"一次整屏同步取图（冷缓存 >1 秒）"摊成多拍，让事件循环每拍都有确定的空档 —— 而不是把 Shell 调用搬进线程。**

### 方向②：前台全屏检测 + 暂停（新增 `foregroundgate.h`）

新建 header-only 的 `ForegroundGate`（`foregroundgate.h`，唯一新文件，已加入 `.pro:81`）：

- **双判据**：
  1. `SHQueryUserNotificationState` 返回 `QUNS_BUSY(2)` / `QUNS_RUNNING_D3D_FULL_SCREEN(3)` / `QUNS_PRESENTATION_MODE(4)`；
  2. 兜底：前台窗口矩形覆盖其所在显示器**整屏**（`GetMonitorInfoW` 的 `rcMonitor`，容差 2px），并排除本进程 / `Progman` / `WorkerW` / `SHELLDLL_DefView` / `Shell_TrayWnd` / `Shell_SecondaryTrayWnd`。
- 用 `rcMonitor` 而非工作区：最大化普通窗口的矩形等于工作区、底边被任务栏截掉 ≥30px，**不会误判**。
- **动态 `GetProcAddress("shell32","SHQueryUserNotificationState")`**，不 `#include <shellapi.h>` —— 该声明被 `_WIN32_WINNT>=0x0600` 守卫，头文件里无法保证自己的 `#define` 排在所有 `windows.h` 之前；动态取址对任何 SDK 配置都成立。
- **800ms 节流缓存** + `invalidate()`，调用点几乎零成本（`fullscreenActive()` 就是比较 + 取时钟）。

**12 处调用点**（11 处"刹车" + 1 处看门狗判定）：

| 位置 | 作用 |
|---|---|
| `desktopmirrorwindow.cpp:1007` `refresh()` | 全屏不刷新；记 `m_fsRefreshPending=true` |
| `desktopmirrorwindow.cpp:964` `processDockIconQueue()` | 全屏不取图 |
| `desktopiconbutton.cpp:327` `processIconQueue()` | 同上（收纳盒/助手侧） |
| `desktopmirrorwindow.cpp:245` `m_bottomTimer` | 全屏不做压底 |
| `desktopmirrorwindow.cpp:263` `m_recyclePollTimer` | 全屏不查回收站 |
| `desktopmirrorwindow.cpp:817` `restoreAllTargets()` | 全屏不碰 z 序（🚨见下） |
| `icongridwindow.cpp:2974` | 层看护停摆 |
| `filesearchwidget.cpp:71` | 同上 |
| `shutdowntimerwindow.cpp:203` | 同上 |
| `todolistwindow.cpp:110` | 同上 |
| `wallpaperwindow.cpp:115` | 同上 |
| `desktopmirrorwindow.cpp:948` `onFullscreenWatchTick()` | **看门狗自身判定**（唯一"永不暂停"的定时器） |

**"暂停而非丢弃"的最终一致保证**：全屏期间被拦下的动作记进待办（`m_fsRefreshPending`），由 `m_fsGateTimer`（1000ms，**永不暂停**）在发现"已退出全屏"时补做一次。看门狗自身不依赖任何会被暂停的定时器；`refresh()` 的全屏分支里还兜底 `if (m_fsGateTimer && !m_fsGateTimer->isActive()) m_fsGateTimer->start();` —— 否则 `setSourceMode()` / 早于 `startMirror()` 的刷新路径下，退出全屏永远没人补做，界面会一直空着。

### ③ 方向③：`refresh()` 前置廉价变化门

新增 `cheapDesktopStamp()`（`desktopmirrorwindow.cpp:911-938`）：**个人桌面 + 公共桌面**（`CSIDL_COMMON_DESKTOPDIRECTORY`）的「路径 + mtime + 直接子项数 + 排序子项名」—— 两次 `readdir` + 两次 `stat`，百微秒级，与秒级的整屏 Shell 查询不在一个量级。

在 `readEntries()` **之前**比较（`desktopmirrorwindow.cpp:1024`）：戳一致且未 `m_forceRescan` → `refresh:cheap-skip` 直接返回，**省掉整轮整屏 Shell 查询**。

**绕过本门的 5 个入口**（都会置 `m_forceRescan = true` 或直接刷戳）：

| 位置 | 原因 |
|---|---|
| `desktopmirrorwindow.cpp:3534` `WM_DESKTOP_NOTIFY` | 该消息**不携带事件类型**，分不清增删与 `SHCNE_ASSOCCHANGED`，一律重扫 |
| `:343` `setSourceMode()` | 条目集合的来源完全变了 |
| `:301` 外观开关（快捷方式小箭头等） | 改外观不改目录 mtime/项数 |
| `:1168` `resetDock()` | 已完整读过一次桌面 → 直接刷戳 |
| `:1051` `refresh()` 内 ListView 未就绪 | 清戳，否则 500ms 后的重试被误挡 → 界面永远空 |

🚨 **两处正确性陷阱（本轮自查发现并规避）**：

1. **提交点必须后移**（`:1112` `if (!m_refreshPending) m_lastCheapStamp = stamp;`）：`layoutButtons()` 可能因"编辑中/菜单中"守卫把请求记进 `m_refreshPending` 并返回 —— 若在扫描前就提交戳，那次补做的 refresh 会被本门短路，**界面永远停在旧图标上**。
2. **`stopMirror()` 清戳**（`:421` 附近）：否则"镜像停止期间用户只是把图标拖到别处"（目录 mtime 与子项名都没变）会让 `startMirror()` 的首刷被误挡、沿用旧坐标。

`!m_lastCheapStamp.isEmpty()` 这个条件**刻意保留**：它是「从未提交过戳 → 必扫」的安全阀。虽然 `cheapDesktopStamp()` 恒含目录路径、实际不会返回空串，但一旦某天两个桌面路径都解析失败使戳为空，去掉它就会变成**永久短路**（宁可多扫一次，不可永不刷新）。

### ④ 方向④：长尾治理

两张图标队列都从"一次干完"改成"每拍到预算为止"，并加"上一拍超预算则本拍让出"：

- Dock 侧：`kIconBurstBudgetMs = 12`（`desktopmirrorwindow.cpp:987`）；队列 > 8 时 `ConditionalHooksGuard hooksPaused(true)` 摘键盘钩子（`:980`）。
- 收纳盒/助手侧：`kIconProcessBudgetMs = 20` + `s_lastBurstMs`（`desktopiconbutton.cpp:287-330`）。

"让出一拍"是必要的：只按预算切分的话，若队列里连续出现长尾项，每一拍都会被自己那条长尾撑满、等于"连续多拍都堵着"；加让出后，事件循环每两拍必有**一拍确定的空档**处理输入与绘制。

### ⑤ 方向⑤：回收站轮询降频

`m_recyclePollTimer` 周期 **9000 → 30000 ms**（`desktopmirrorwindow.cpp:255` 附近注释，构造处改）。本机实测该查询 **48~61 ms/次**（全盘遍历），30s 周期下摊薄到可忽略；状态翻转本就是低频事件，用户无感。同时加全屏门。

### ⑥ 方向⑥：全屏跳过节拍 Z 序

`m_bottomTimer`（`desktopmirrorwindow.cpp:245`）+ 5 个窗口的 `m_layerKeeper`。理由：全屏程序对 z 序改动最敏感（一次 `SetWindowPos` 就可能让老 DX8 游戏切换显示模式 → 黑屏 + 输入僵死），且用户此刻根本看不见那些面板。`restoreAllTargets()` 更甚：它每 150ms 对每个受保护窗口做 `IsIconic` / `IsWindowVisible` / `DwmGetWindowAttribute`（跨进程 DWM 代理调用），必要时还会 `ShowWindow` / `SetWindowPos`。

🚨 **`restoreAllTargets` 的门必须在 `s_restoring = true` 之前**（`:817`，紧跟注释警告）：该函数是"进入即置真、末尾才落旗"的防重入结构，任何提前 return 若放在置真**之后**，标志会永久为真 → 三个窗口再也救不回来。全屏门放在第一行，`s_restoring` 都没碰，绝对安全。

## 三、一处必须说明的偏离

**方向①我没有改成工作线程。** 这不是偷懒，是"改了会更糟"：Shell 图标提取是 STA COM，搬进工作线程是**已知会死锁/崩溃**的路径（本项目历史教训），而实测真正的热点是逐项 `SHGetFileInfoW` 而非扫描函数本身。改为"**缓存命中同步（稳态零变化）+ 冷项异步队列（首刷/新增分帧）**"后：

- 稳态刷新（绝大多数情况）：`cachedIcon()` 命中 → 同步设图，**与旧实现逐字节一致**；
- 冷缓存（首刷、桌面新增）：不再一次性阻塞 >1 秒，而是摊到多拍，每拍 ≤12ms。

方向上与报告一致（把重活从"一次阻塞"变成"多次短阻塞"），手段上规避了线程化 Shell 的死锁风险。

## 四、"不破坏现有功能"的三道保证

1. **不改语义，只加时机控制**：所有改动都是"提前返回 / 延后执行 / 记待办"，没有删除或改写既有逻辑分支；`Q_UNUSED(force)` 之类保留原签名。
2. **稳态可逐字节比对**：前台非全屏 + 桌面无变化时，`fullscreenActive()` 恒 false（不触发任何新分支）、`cheapDesktopStamp()` 命中时走的是"结果与旧指纹短路完全相同"的路径、`cachedIcon()` 命中时设的是同一张 `QIcon`。即**日常使用路径与改动前完全重合**。
3. **回归哨兵**：断言脚本里既有 5 条既有字符串（`RawInput`、`当前版本：0.1.0`、`距桌面顶部始终留出 10 逻辑像素`、`refresh:enter`、`refresh:done`）全部 PASS —— 说明既有代码路径仍在产物中。

### 补充：方向①的"只摘键盘"（超出报告的一项加固）

报告只要求"重活期间摘钩"。实施时把摘钩**精准化**为"只摘键盘、保留鼠标"（`lowlevelhookmanager.h:91-115`）：

- 键盘是 `WH_KEYBOARD_LL`，**同步回调到安装线程** → 必须摘；
- 鼠标已改 Raw Input（`rawmouse.h`，`RIDEV_INPUTSINK`），**异步**、只堆积在自己的消息队列，**不阻塞系统输入链** → 摘它零收益，还会引入 `RIDEV_REMOVE→RIDEV_INPUTSINK` 重注册与 `desktopimmunityfilter` 交叉验证的竞态。

同时用 RAII 守卫（`SuspendHooksGuard` / `ConditionalHooksGuard`，`desktopmirrorwindow.cpp:162-190`）包住 `refresh()`、`layoutButtons()`、两张图标队列、收纳盒/搜索窗的重活 —— 因为这些函数里有多条 early return，手工成对调用漏一处就会**键盘钩子永远回不来**（F2/Delete 静默失效）。

## 六、后续观察建议

本轮完成了"静默期不再卡"的全部前置条件，但**真正的游戏内验证需要在用户机器上实跑**（沙箱无法启动全屏游戏）。建议观察：

1. 进全屏游戏后（`Ctrl+Alt+Del` 或切出）确认 Dock / 收纳盒**不闪不动**、Z 序不乱；

3. 若仍有卡顿，用 `refresh:cheap-skip` / `refresh:enter` 埋点日志区分是"扫描"还是"取图"在超时。
