## 一、问题 1：分类来回切换 → 鼠标移动变慢（卡顿严重）

### 1.1 根因（两条并存，一条是主要矛盾）

**① 主因：缓存页"顺序一变就推倒重建"，重建的代价是重新排队取图标**

分类页缓存（`parkCurrentGridPage` / `adoptCachedGridPage`）的命中判据是：

```cpp
const bool stale = (page.viewMode != m_viewMode) || (page.signature != pageSignatureOf(currentItems()));
```

`page.signature` 是**顺序敏感**的 `sourcePath` 序列。于是任何一次**顺序**变化（拖拽排序、Dock 侧同步顺序、
顺序键重排、`applyItemOrder` 结果差异…）都会让这一页被判 `stale`，走进这条路径：

```
deleteLater 整页按钮  →  重新 new 每个 DesktopIconButton  →  每个按钮重新入队取图（s_iconTimer 30ms / 每拍 1 个）
```

一个几十上百项的"图标很多"的分类，重建后就是**几秒的连续界面占用**：GUI 线程每 30ms 被唤醒一次去走
Shell 取图（单次几 ms ~ 45ms，机械盘 + 安全软件抢盘时更慢）。表现就是**鼠标移动发涩、拖动一顿一顿**，
而且"来回切换"会让它反复发生。

> 事实是：**顺序变化根本不需要重建按钮**。按钮、图标位图、信号连接全都还能用，
> 只需要把它们按新顺序放回布局 —— 同一批控件，零销毁、零取图。
> 这与上一轮"收纳盒交换位置不必重新加载"是同一个道理。

**② 次因：每次切分类都同步刷盘**

`saveCurrentCategory()` 的调用点就是 `activateCategoryTab()` / `setCurrentCategory()` —— **每一次**分类切换。
它内部是 `saveValue` + **`sync()`（同步刷 INI）**。机械盘 + 360 抢盘下单次可达数十~数百 ms，且全在 GUI 线程。
它要存的只是"下次打开默认选中哪个分类"，晚几百毫秒写、甚至偶尔丢一次都完全无感。

**③ 次因：换页期间逐控件重绘 + 冗余的 O(n) 遍历**

- `park`（n 次 `setParent` → 隐藏）与 `adopt`（n 次 `setViewMetrics` + `addWidget` + `show`）全程没有关重绘，
  每个按钮都会让系统排队一次中间态重绘/布局失效；
- `adoptCachedGridPage()` 末尾无条件 `enableChildMouseTracking(m_gridContainer)`：递归遍历整棵树、
  对每个按钮重新 `installEventFilter` —— 而按钮在 `applyGridItems` 创建时就已被 track 过，
  `setParent` / `addWidget` 都不会摘掉已安装的事件过滤器（filter 挂在 QObject 上，与父子关系无关）。纯白跑。
- `relayoutGridForGeometry()` 每次都"全摘再全放"整页按钮（O(n)），而**列数没变时行列位置根本没变**。

### 1.2 修复

| # | 改动 | 位置 | 性质 |
|---|---|---|---|
| P1 | **顺序变化改为「原地复用 + 重排」**：新增 `HIT-RESORT` 出口 —— 若"集合相同、仅顺序不同"，就把**同一批按钮**按新顺序放回布局（不 deleteLater、不重建、不重取图）；真的增删条目才走原重建 | `adoptCachedGridPage()` | 质变（消灭主要矛盾） |
| P2 | **落盘防抖**：值未变不写；连续切换合并为"停止切换 300ms 后写一次"；析构兜底 `flushCurrentCategory()` | `saveCurrentCategory()` / 新增 `flushCurrentCategory()` | 零功能变更 |
| P3 | **换页期间关闭重绘**：`park + prepareGridLayout + adopt/apply` 全程 `setUpdatesEnabled(false)`，结束后恢复并 `update()` 一次 | `switchCategoryPage()` | 零功能变更 |
| P4 | **删除冗余的 `enableChildMouseTracking`** | `adoptCachedGridPage()` | 零功能变更 |
| P5 | **几何重排加列数早退**：列数未变直接 return（拖动窗口边缘是高频 resize，每像素一次） | `relayoutGridForGeometry()` | 零功能变更 |

**P1 的安全兜底**（任何一步对不上就退回原来的全量重建，原行为永远是兜底）：

- 视图档位不同 → 重建；
- 签名排序后集合不同（真增删）→ 重建；
- `sourcePath` 归一化 key 有对不上 / 数量不符 → 重建（`why=mapMiss` / `why=content`）。

**P1 的一致性**：重排后页内顺序 = 该分类当前数据顺序；下次 `park` 时按实际布局顺序重新记录签名，天然一致。
选中集合不受影响（`switchCategoryPage` 入口本就 `clearSelection()`），分类页缓存不受影响。

## 二、问题 2：拖拽多个图标后进入多选态，且点击收纳盒取消不掉

### 2.1 根因（三条并存，所以只补任何一处都不够）

选中集合 `m_selection` 是本窗口的私有状态，而**三种最自然的"取消选中"手势全都到不了清除代码**：

1. **点网格空白** —— 网格可视区被 `QScrollArea` → `viewport` → `m_gridContainer` 层层覆盖。
   点击落在 `viewport` 上，由 `IconGridWindow::eventFilter` 按 hover / 拖放语义消费掉，
   **永远不会转发给 `IconGridWindow::mousePressEvent`** —— 那里那句 `clearSelection()`（注释写明"点空白＝取消选中"）
   实际上几乎从未被执行到。
2. **全屏收纳（`m_fencesMode`）** —— `mousePressEvent` 开头就 `QWidget::mousePressEvent(event); return;`，
   连那点机会也没有。
3. **点收纳盒 / Dock / 设置中心 / 其它窗口** —— 事件完全在另一棵 QWidget 树上，本窗口无从得知。

现象完全对得上用户的描述："**多个图标进入选中状态，而且点击收纳盒，状态不能取消，必须鼠标一个一个的点击**"
—— 唯一还能取消的入口只剩"点击另一个图标"（`selectExclusive` 会清掉其余），所以只能挨个点掉。

### 2.2 修复

`IconGridWindow` 构造时挂 **应用级** 事件过滤器 `qApp->installEventFilter(this)`（析构摘除），
在 `eventFilter` 新增 `watched == qApp` 分支：

```cpp
if (watched == qApp && event->type() == QEvent::MouseButtonPress) {
    if (m_selection.isEmpty() && !m_anchor) return false;          // 常态零开销
    if (button == Left || button == Right) {
        QWidget* hit = QApplication::widgetAt(me->globalPos());
        if (!qobject_cast<DesktopIconButton*>(hit)             // 命中图标 → 放行（按钮自己要处理单击/Ctrl加选/Shift范围选）
            && !qobject_cast<QLineEdit*>(hit))                 // 命中输入框 → 放行（改名途中不能抹选中）
            clearSelection();                                   // 其余一律清空 = Windows 桌面"点空白取消选中"
    }
    return false;
}
```

**为什么要排除图标本身**：按钮的 `mousePressEvent` 会 `emit selectionRequested(this, ctrl, shift)`；
若在这里先清一遍，`Ctrl` 加选与 `Shift` 范围选会被当场清空 —— 加选功能会失效。

**为什么要挂 `qApp` 而不是本窗口**：上面根因 ①②③ 里的 ② ③ 走的都不是本窗口的事件路由；
`qApp` 过滤器能看到**本进程内**所有窗口（Dock / 各收纳盒 / 设置中心 / 对话框）的鼠标按下，
所以"点收纳盒空白""点 Dock""点设置中心"现在都能取消选中。

**开销**：仅当本窗口确实存在选中项时才做那一次落点查询；常态下一句话早退。每个 IconGridWindow 实例一个过滤器
（主窗口 1 个 + 每个盒窗口 1 个），数量很小。

**已知边界**：点击**其它进程**窗口（浏览器、Explorer）不会触发（事件不进本进程）—— 这与 Windows 桌面
"点别的程序时桌面选中仍保留"的行为一致，非缺陷。

## 五、本轮**没有**动的（避免越界）

- 图标取图队列参数（`30 ms × 每拍 1 个`）：13:28 是用户主动从 2 改成 1 的，不擅动。
