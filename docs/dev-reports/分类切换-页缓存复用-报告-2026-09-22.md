# 收纳盒分类切换「不重复刷新」——分类页缓存 报告

- 日期：2026-09-22
- 用户口径：**分类切换时对应内容不要每次都重新刷新一遍；只在程序启动后第一次切换时加载，
  加载过之后再切换就不用再刷新。**
- 结论：已实现并编译通过（**未代跑试验台**，请你亲自测）。

---

## 一、原先为什么会"每次都刷新"

`IconGridWindow::activateCategoryTab()`（点击 / 悬停切换的唯一入口）末尾无条件调用 `rebuildGrid()`，
而网格是**单容器 + 单布局**：

```
rebuildGrid() → applyGridItems(currentItems())
                 ├─ 把 m_gridLayout 里的按钮全部 takeAt + deleteLater（销毁）
                 └─ 按当前分类 items 逐个 new DesktopIconButton（构造 + 取图标 + 建连接 + addWidget）
```

数据（`m_allItems`）本来就在内存里、不用重新扫盘，但**按钮每次都重建**：分类图标几十~几百个时，
切换一下就要构造同样数量的窗口部件并重取图标 —— 肉眼看得到一次刷新/闪动。

## 二、实现：按分类缓存"已建好的按钮页"

核心思路：**按钮不再销毁，切走时收起来、切回时装回去**。

| 环节 | 做法 |
|------|------|
| 隐藏宿主 | 新增 `m_pageCacheHost`（`QWidget`，挂在**本窗口**下、`hide()`）。🚨刻意**不**放进 `m_gridContainer`，这样它的内容既不被网格布局接管，也不会被 `allIconButtons()` 的 `findChildren(m_gridContainer)` 扫到（缓存按钮不该参与 F2/Delete 与编辑判定） |
| 切走 | `parkCurrentGridPage(cat)`：把布局里的按钮逐个 `takeAt` 后 `setParent(m_pageCacheHost)`（保活、立刻隐藏、**信号连接不受换父影响**），并以 `cat` 为键登记进 `m_categoryPages` |
| 切回 | `adoptCachedGridPage(cat)` 命中则按**当前列数**（窗口可能已被缩放）重新 `addWidget` 装回并 `show()`；未命中则走首次构建 |
| 首次 | 走原 `applyGridItems()` 构建一次；下一次切走时自然被 park 进缓存，之后切回就是复用 |

配套改动：

- `applyGridItems()` 里的**布局度量计算**抽成 `prepareGridLayout(items) → GridMetrics`
  （列表档行宽 / 单元格尺寸 / 图标像素 / 间隔 / 列数 / 行数 + stretch 清理），
  **"首次构建"与"装回缓存"共用**，保证两条路径的布局参数完全一致、不会漂移。
- `activateCategoryTab()` 改走 `switchCategoryPage(from, cat, parkOld)`，不再直接调 `rebuildGrid()`。
- 新增 `discardCurrentGridPage()`（原 `applyGridItems()` 开头的清空逻辑抽出来复用）。

### 缓存失效（关键正确性）

| 规则 | 说明 |
|------|------|
| 命中条件 | **数据代次 + 视图档位 +（列表档）行宽** 三者全等 |
| 失效时机 | `rebuildGrid()` 开头调用 `invalidateCategoryPages()`：代次 +1 并销毁全部缓存页 |
| 为什么够 | 任何数据变更（新增/删除/改名/拖放/搜索/桌面刷新/换视图档）最终都走 `rebuildGrid()` ⇒ 缓存绝不会把**过期内容**显示给你 |
| 上限 | 最多缓存 **6 页**（`m_pageOrder` 记最近使用顺序，超出丢最久未用页），防止分类多 + 图标多时内存累积 |
| 重复激活 | 激活当前分类（含悬停划过当前标签）**直接返回**，不换页不刷新 |

### 明确不走缓存的三种情况（保持原行为）

1. **全屏 / 常驻盒子视图**：按分类铺盒子（`buildFences`），与网格页无关；
2. **搜索态**：网格里显示的是跨分类搜索结果，那张页不属于任何分类 ⇒ 切分类时 `parkOld=false`，
   直接销毁（不污染缓存）；
3. **冻结态**（右键菜单 / 内联重命名 / 图标拖拽进行中）：与 `rebuildGrid` 同源理由（原生模态循环里
   的 `deleteLater` 会当场析构正在交互的按钮）⇒ 退回原重建路径（记账，冻结解除后补做）。

## 六、两点已知取舍（如与你预期不符请说一声）

1. **点当前分类标签不再刷新**（原先会重建一遍）。数据变化由桌面监控自动触发重建，所以不影响内容实时性；
   若你想要"点当前标签＝手动刷新"，加一句即可。
2. 同一分类被缓存后，**滚动位置**沿用当前滚动条（不重置到顶部）—— 视为更好用；如需每次回到顶部也能改。
