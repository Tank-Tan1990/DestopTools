一、产品概述

DestopTools 是一款面向 Windows 桌面的图标整理与效率工具，借鉴 360 桌面整理的体验范式，通过接管原生桌面图标并自建可视化层，帮助用户把混乱的桌面组织为可分类、可收纳、可备份、可个性化的有序工作空间。

1.1 产品定位

在"原生桌面图标杂乱、缺乏分组与收纳手段"这一普遍痛点上，DestopTools 提供一层轻量的桌面治理层：它不改变文件在磁盘上的位置，只重新组织"桌面上如何呈现与管理图标"。产品定位于系统增强型效率工具，而非文件管理器。

1.2 目标用户

  • 重度桌面使用者：桌面堆积数十至上百个快捷方式 / 文件的办公人群；
  • 追求整洁的用户：希望桌面分区、分类、按需隐藏图标的强迫症型用户；
  • 多项目工作者：通过"收纳盒 + 分类"隔离不同项目的桌面资源；
  • 注重个性化：对主题色、透明度、圆角等视觉风格有要求的用户。

1.3 核心价值（解决的痛点）

1.5 设计理念

产品的三条底层原则贯穿所有功能设计：

原则一不打扰系统，只治理呈现。 文件物理位置不变，所有整理仅作用于"桌面呈现层"，降低用户迁移与误删风险。

原则二全局交互零摩擦。 F2/Delete、双击隐藏、框选等高频操作通过系统级钩子直达，无需聚焦窗口。

原则三性能即体验。 鼠标流畅度是桌面工具的生命线，所有重活（Shell 取图、刷新、置顶）均以"不阻塞 GUI 线程"为红线。

二、产品架构

DestopTools 采用单进程多顶层窗架构，以"桌面治理层"为核心，将不同能力拆分为互相协作的悬浮窗与后台服务。

2.2 关键悬浮窗与 z 序关系

产品存在一组"band 窗口"（Dock 图标层、收纳盒、助手面板）与位于其上的弹框体系。z 序设计遵循：弹框 > 全部 band 窗口 > 其它正常程序。Dock 因铺满主屏被压至最底（HWND_BOTTOM），收纳盒与助手在其上；所有模态弹框通过错峰 raiseAboveBandWindows 保证不被 band 窗口遮盖。

三、功能设计（产品设计视角）

以下按用户场景 → 设计目标 → 设计要点三段式描述每个核心功能，体现"为什么这么做、做成什么样"。

3.1 桌面图标整理（Dock）

用户痛点原生桌面图标无法分组、难以隐藏、重命名/删除步骤繁琐，且多屏与高 DPI 下观感不一致。

设计目标提供一层"替身桌面"：接管原生图标并隐藏，在自有分层窗上自绘图标，保持原生观感但获得更强的组织与交互能力。

设计要点

  • 接管采用 owner 双保险（绑定 SHELLDLL_DefView + 免激活属性），避免被系统重置；
  • 自绘图标层铺满主屏并压至最底，图标与标签并集命中（含 4px 间隙），避免"点空白误清空选中"；
  • 内联重命名仅 Enter/Esc/点框外三通道提交；新建项自动弹框，按"会话事实"判断而非名字形状；
  • 删除以"图标矩形与回收站相交 ≥1/4"为判据，统一走系统回收站（可撤销）；
  • 框选多选采用 Qt + 低级鼠标钩子双通道状态机，保证全局拖动顺滑。

3.2 收纳盒与分类

用户痛点桌面图标一旦变多便无从归类；切分类时整屏重刷导致卡顿；盒内排序被刷新"还原"。

设计目标把桌面划分为可拖拽的"收纳盒"，并用分类标签在盒内/盒间切换视图，切换零刷新、排序可持久。

设计要点

  • 收纳盒由桌面空白拉框（≥48×36 逻辑像素）创建，生成前就地弹出确认框，位置/大小等于所画之框；
  • 分类标签页支持"点击切换 / 悬停切换（停稳 140ms）"两种模式，热更新即时生效，无需重启；
  • 视图提供大/中（默认）/小/列表四档，列表档整块自绘以保证"图标贴左 + 文字紧随"；
  • 分类页缓存：切走换父、切回复用，以"逐页内容签名"命中，避免重复取图与重建；
  • 盒内仅换顺序时走原地复用（不销毁重建按钮），盒窗口顺序为权威数据，防止刷新"还原"用户排序。

3.3 桌面备份与恢复

用户痛点精心整理的桌面布局一旦因重装/误操作丢失，无法快速还原；普通截图无法记录完整配置。

设计目标提供 360 式备份网格，一键保存当前全部桌面配置，并可在任意时刻原样恢复。

设计要点

  • 备份实体包含两份配置（主设置 DestopTools.ini ＋ 分类库 categories.ini）、备份瞬间桌面缩略图、元信息；
  • 应用备份采用"退出后覆盖 + 拉起新实例"编排，确保运行期各窗口持续落盘的值不被覆盖，并正确处理单实例管道；
  • 截图采用 Win32 BitBlt + CAPTUREBLT 而非 Qt 截屏（后者在 DWM 下只抓壁纸）；截屏期间仅将本窗移出屏幕（move(-32000,-32000)），杜绝透明模态窗死锁。

3.4 待办与提醒

用户痛点桌面工具缺少轻量待办；到期提醒易被忽略，且反复弹窗打扰。

设计目标在桌面侧常驻一个不打扰的待办与提醒机制，到期只提醒一次、可确认清除。

设计要点

  • 到期提醒只发一次 reminderDue，清除仅当用户点"OK"；Esc/关闭不清除，重启后再次提醒；
  • 待办行首以喇叭图标闪烁标记（两版预渲染 pixmap + 450ms 定时器互换，避免离屏渲染常驻负担）；
  • 闹铃出声由独立开关控制，消费端每次实时读盘，尊重用户静音偏好。

3.5 主题与个性化

用户痛点原有透明度把线框与文字一起淡化、且不作用到独立弹层（菜单/下拉），观感撕裂。

设计目标透明度只作用于背景，线框/文字恒定；主题色与透明度对所有窗口、弹层、菜单统一生效。

设计要点

  • 双 alpha 通道：alphaF（线框/文字恒定）与 bgAlphaF（背景随滑块），全项目背景色字面量统一经 applyTokens 注入；
  • 菜单透明度通过"首次弹出前重建平台窗（加 WS_EX_LAYERED）"实现真正半透明，长期持有的菜单挂 aboutToShow 防样式烘死；
  • 占位文字颜色钉死为固定灰，不随主题色变黑；关于页 Logo 等"烤进像素"的图形在切换主题时重建；
  • 应用图标以"谭/征"定制生成，十档尺寸编入 exe 资源。

3.6 快捷操作

用户痛点桌面图标想一键隐藏、想随手圈一块区域收纳，但系统无原生手段。

设计目标把两个高频意图做成开关：双击空白隐藏全部图标；空白拉框直接建收纳盒。

设计要点

  • 双击隐藏需自判双击（低级钩子不送 WM_LBUTTONDBLCLK）；隐藏态仅内存、并在每次刷新末尾重套，避免被冲掉；
  • 拉框建盒复用既有橡皮筋机制，Ctrl 拉框保留为框选逃生口；建盒模式自绘强调色与"松开即创建收纳盒"提示。

3.7 文件搜索与助手面板

用户痛点桌面找文件靠肉眼翻；缺少常驻的轻量入口。

设计目标提供一个可长期存活、可拖动的快速搜索窗与助手面板（搜索/时钟/闹铃）。

设计要点搜索窗与助手面板均为无边框窗，自实现拖动；长期存活窗加层级看护，仅在确实被 band 窗口压住时才救回，避免与正常 z 序变化打架。

3.8 自动对齐（窗口吸附）

用户痛点手动摆放收纳盒/助手难以对齐，贴顶边也不美观。

设计目标拖动时磁吸相邻窗口与工作区边缘，并以网格兜底对齐；顶部留白统一。

设计要点磁吸优先、网格兜底；磁吸阈值 8 逻辑像素（不乘 DPR）；网格步长等于折叠盒高度；顶部统一留白 10px 且与网格解耦；拖动时按 Alt 临时脱离吸附。

3.9 设置中心

用户痛点大量设置项"写盘了却没生效"或"改完要重启"，且同页单选项互相覆盖。

设计目标设置中心作为统一配置入口，改动即时热更新，单选项互不干扰。

设计要点设置消费采用"构造读一次 + 广播热更新"两段式；同页多对单选钮各自绑定 QButtonGroup，杜绝 autoExclusive 连坐；透明度/主题色/分区标签切换等逐项接通消费端。

四、功能实现（工程实现视角）

以下从工程角度说明关键能力是如何落地的，以及攻克了哪些硬骨头。所有实现均在不改动功能语义的前提下完成。

4.1 无边框分层窗框架

技术方案：所有 band 窗口与弹框均为 FramelessWindowHint + WA_TranslucentBackground 的顶层窗，自行实现拖动（press 记偏移、move 重定位，可拖区排除输入/列表/按钮）。弹框遵循"三件套"：特定 flags（禁 Dialog，避免被 Dock 压底）+ 错峰 0/60/200ms 升层 + nativeEvent 清除 SWP_NOACTIVATE。z 序守卫写在各窗 nativeEvent 的 WM_WINDOWPOSCHANGING 中（全局 filter 看不到该同步消息）。
难点攻克：Qt 在 show() 后仍会沿 parent 链补一次 z 序调整，单次升层会被覆盖 → 必须错峰多轮；raiseAboveBandWindows 须先求"最上层 band"作唯一 anchor 再插一次，否则多 band 时被夹在中间或压到某 band 之下。

4.2 全局交互（钩子 → Raw Input）

技术方案：F2/Delete 通过 WH_KEYBOARD_LL 实现（挂件窗拿不到键盘焦点）；双击隐藏/框选通过 WH_MOUSE_LL。关键约束：钩子回调路径禁同步文件 I/O（走非阻塞诊断日志），物理坐标须 phys/dpr 换算，闸门用 registered(token) 而非 active() 防嵌套计数坑。
难点攻克：鼠标卡顿根治——低级鼠标钩子是系统同步回调到安装线程，GUI 线程一被占用全系统光标等待。最终将鼠标钩子迁移至 Raw Input（WM_INPUT，异步投递、不进系统输入链），从根本上解除"堵 GUI 线程＝堵全系统"的因果链。

4.3 性能治理

技术方案：① Shell 取图缓存——resolveShortcut() 原对每个 .lnk 走完整 COM 取图，被键盘钩子放大成全系统排队；改为按"路径|mtime"缓存 + 512 上限。② 静态缓存限容（图标缓存 ≤2048）。③ 事件驱动替代轮询——以 SetWinEventHook ×4 取代 150ms 全屏状态轮询。④ 收纳盒局部刷新——只换顺序走原地复用，杜绝整屏重刷与重取图。
量化收益：分类切换由"每切一次卡一次"变为零刷新复用；图标队列由 30ms×2 摊成 ≈5s 卡窗降至 30ms×1；GUI 线程周期性占用被系统性削减。

4.4 主题与透明度系统

技术方案：全项目背景色字面量仅两种，全部包在 applyTokens 中，故只改该函数即全应用生效。双通道分离线框与背景 alpha；滑块 setTracking(false) 保证"拖滑块零下发、松手一次 repolish"。菜单透明度通过对 QMenu 在首次 popup 前加 FramelessWindowHint|NoDropShadowWindowHint + 透明属性触发平台窗重建，使其拿到 WS_EX_LAYERED。
已知遗留：QComboBox 下拉弹层同样缺 alpha 合成位，且同一手法修不了（其 container 会重置 flags），目前下拉背景只能合到黑底；表头虽生效，但因叠加层数多导致"透感"弱于单层。

4.5 缓存与局部刷新策略

技术方案：分类页缓存以"逐页内容签名（顺序敏感）"命中，切回直接复用按钮而非重建；盒内增量刷新 applyItemsDeltaInPlace 只在"集合相同、仅顺序不同"时按新顺序放回同一批按钮；盒窗口顺序由窗口权威数据承载，防止刷新"还原"用户排序。

4.6 崩溃取证与诊断

技术方案：统一诊断开关仅由 INI [Diagnostics] traceEnabled 控制（默认 false；false 时 trace.log 与 crash.log 均不写）。崩溃取证挂 VEH（AddVectoredExceptionHandler）先于 signal/SEH 获取真异常码与地址；release 版以 DestopTools.map 为唯一符号源，配 tools/addr2func.py 反查栈帧。CrashTrace::mark 仅内存缓冲、崩溃才输出，里程碑事件用 event() 直落盘。
难点攻克：跨进程 HIMAGELIST 必失效导致 COMCTL32 内部 AV（"运行一会儿自己关闭"真凶）；以 SEH 关进熔断器，失效 8 次/60s 降为 1 次，杜绝进程级致命自关。

border 一律 alphaF（恒定）

六、质量保障与交付

6.1 验证体系

  • 链接产品 .obj 的探针台：tools/alphatest（主题逻辑）、tagprobe（标签切换端到端）、scprobe（设置持久化）、menualpha/popupprobe/wndprobe（弹层透明度实测）、panelprobe/placeholderprobe（占位色）；均自动备份/还原用户 INI。
  • 双编码产物断言：QStringLiteral 落 UTF-16LE、信号/资源名可能是 ASCII/UTF-8，任一编码命中即算存在，确保新码确实编进 exe。
  • 崩溃取证：VEH + .map + addr2func.py 形成完整栈回溯链。
